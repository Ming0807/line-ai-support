## Findings and current status

The initial source had a substantive OCR waiver gap. For an `OCR_REQUIRED` extraction warning, the policy required an edited preview, nonempty affected page text, and changed-page evidence, but did not require that warning's saved disposition be `CORRECTED`. Because the review schema permits `FALSE_POSITIVE`, a changed but still review-marked OCR page could otherwise pass the quality gate with a false-positive disposition. The current source closes this: it requires the exact server-derived OCR warning disposition to be `CORRECTED`, a current `EDITED` preview, evidence that each affected page changed and remains nonempty, and zero replacement characters. Current extraction/analysis are re-created on append; the original parser warning remains in the edited extraction history.

The initial source also did not bind the plan checksum to an independently trusted source checksum, and its exact-coverage check did not bind every chunk's `requiresReview` flag to the canonical warning projection. Current source closes both gaps: `validatePublicationReview` requires the trusted checksum argument and compares it to `plan.sourceChecksum`; PAGE and TABLE checks now require the same conservative `requiresReview` value derived from page/table state and `locatedReviewApplies` as the builder. The final service must pass the immutable checksum from its authorized job snapshot and recheck it at the final lock, as root's integration contract specifies.

No unresolved correctness issue was found in the scoped files after these fixes. The policy requires a saved v2 review bound to current job/extraction/review revisions and the acknowledged plan digest; required metadata and all five attestations; server-derived warning references with a reason for every disposition; official YRU source metadata for PUBLIC; and a hard PUBLIC sensitivity block independent of false-positive dispositions. Unsupported `STRUCTURED` and `BOTH` modes fail closed while RAG can preserve a dataset candidate without DDL. The existing schema constrains all five actions and permits whole-document `CANCELS` only as `ADD_ADDITIONAL` with an exact target; this helper intentionally preserves those choices for later database resolution and does not claim target/family authorization or publication effects.

Located-plan validation strictly copies and bounds the full plan, enforces fixed E5 identity, token/byte limits, contiguous indexes, supported same-format locations, compatibility-field shape/format constraints, PAGE/TABLE range constraints, and the canonical digest. The publication policy checks lossless PAGE slices including overlap and every TABLE row/cell (including empty cells) against the current extraction and exact source locations. The exported digest refactor preserves the prior canonical SHA-256 payload shape; the validation test reconstructs that old payload and matches its digest.
