## Executive findings (under 400 words)

- **P1 — Dashboard widgets present invented operational data.** The donut uses fixed SVG segment lengths while its legend computes live ticket percentages (`app/(dashboard)/dashboard/page.tsx:191-199,208-214`); weekly bars are fixed values (`:323-336`); the urgent-ticket “progress” is `count × 25%` (`:308-312`). The “AI models enabled” tile counts providers rather than models; when no providers are loaded it displays `0/1` while the progress fill defaults to 100%, and providers load only for SUPER_ADMIN (`:58-70,356-365`). This is misleading operational data. Overview §30 says the homepage “may have” its eight listed metrics, so they are examples rather than a fixed acceptance checklist; displayed indicators must still be real (`docs/requirements/sources/original-overview.th.md:998-1016`; `docs/agents/GEMINI_UI_UX_PROMPT.md:36`). The 13 capability modules in §31 remain in scope (`docs/requirements/sources/original-overview.th.md:1021-1051`; `docs/architecture/YRU_V1_DESIGN.md:116`).
- **P2 — Several controls imply behavior they do not provide.** The scope pill is not interactive, search is `readOnly`, the notification bell is a noninteractive `div`, and the “latest actions” tab has no handler (`app/(dashboard)/dashboard/page.tsx:78-96,109-120,224-235`). The report calls this a tabbed activity feed and says Knowledge has tabs, but the former is a ticket queue and the latter is a catalog section followed by imports (`docs/reports/GEMINI_UI_UX_REPORT.md:38-40`; `app/(dashboard)/knowledge/page.tsx:18-37`). The originating prompt explicitly says not to show controls that do nothing (`docs/agents/GEMINI_UI_UX_PROMPT.md:35`).
- **P2 — Assistance failure is silent and weakens manual recovery.** The GET request failure is swallowed and sets assistance to `null`; family/department options then come from empty arrays, with no explicit error/retry state. The summary still says fields were extracted/classified (`app/(dashboard)/knowledge/import/review-form.tsx:247-267,371-373,401-430,479-507`). Add a visible unavailable/retry state and a real reference-backed manual path. This misses the explicit failed-assistance recovery and named-choice acceptance (`docs/architecture/IMPORT_ASSISTANCE_DESIGN.md:21-27`; `docs/agents/GEMINI_UI_UX_PROMPT.md:49-53`).
- **P2 — The dashboard module map is incomplete.** The shell links only Dashboard, Tickets, Knowledge, and Providers (`app/(dashboard)/nav-bar.tsx:32-84`). Incidents, Departments, Activities, Usage, Analytics, Logs, and Settings have no corresponding page surface in this snapshot. The source requires all 13 module functions, but permits grouping Providers, Models, and Fallback on one route (`docs/requirements/sources/original-overview.th.md:1021-1051`; `docs/architecture/YRU_V1_DESIGN.md:116`).
- **Snapshot dependency/report mismatch.** The reviewed worktree lacks the catalog/family/document API route files while its plan says they exist (`docs/ui/GEMINI_DASHBOARD_PLAN.md:126-127`); the current root checkout contains all three routes. Treat this as an old-snapshot integration mismatch, not a present root API gap. The Gemini report also names a POST assistance endpoint, while the UI and design use `GET /api/knowledge/imports/[id]/assistance` (`docs/reports/GEMINI_UI_UX_REPORT.md:109`; `app/(dashboard)/knowledge/import/review-form.tsx:247`; `docs/architecture/IMPORT_ASSISTANCE_DESIGN.md:13`).

Visual home/sidebar/no-green direction matches latest steering. Existing ticket filters/actions, provider/model ordering, per-model tests, HTTP/quota observations, fallback preview, duplicate preview, receipt preflight, and five-attestation RAG approval gate are retained baseline behavior, not newly implemented here (`app/(dashboard)/knowledge/import/import-form.tsx:247-267`; `app/(dashboard)/knowledge/import/approval-panel.tsx:58-61,115-123,150-173`).
