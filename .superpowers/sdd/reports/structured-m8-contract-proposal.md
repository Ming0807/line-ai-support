# Structured M8 contract proposal (STR-01 / STR-02)

**Date:** 2026-10-06
**Scope:** source-grounded planning proposal only; no product/schema/test/plan changes and no live corpus approval. This report is not an acceptance or publication claim.

## Authority and present boundary

The fixed data scope is seven datasets, with `university_systems` included by DEC-027 even though master §41's illustrative registry omits it. The exact table names and columns below come from master §12. CH012/CH018/CH038/CH041/CH042/CH050 and USR-IMPORT5 remain partial/planned for structured mapping, fixed structured search, and M8. DEC-027 says STRUCTURED/BOTH remain unavailable until the mapper/schema exists; selected RAG remains allowed, with no silent downgrade or DDL. The current code reflects this: `datasetTypes` and the `search_structured` enum contain all seven codes, but `validatePublicationReview` accepts only RAG and `structuredSearch` has no installed implementation. Keep that fail-closed boundary until STR-01/02 is accepted.

The import continuation plan places M8 after PUB-01…04 and explicitly calls for all seven schemas/mappers/search/citations and atomic BOTH publication. The existing publication service prepares outside the SQL transaction and atomically writes the RAG document/version/chunks/receipt. M8 should extend that transaction only after a trusted pure preparation result exists; it must not move embedding, parsing, or other network work inside SQL. DEC-028 requires document/chunk/structured/receipt consistency. Master §50 lists document/version/chunk/structured writes and one rollback boundary. Original versioning rules retain old versions and filter current/effective/authority/applicability before similarity. Master §62 ranks current/effective, authority, department relevance, semantic similarity, then freshness.

## Pure reviewed mapper and provenance contract

Proposed pure boundary: `prepareStructuredRows({dataset, extraction, savedMapping, binding, registry}) -> {dataset, rows, cellSources, mappingDigest, binding}`. It must be deterministic and have no database, network, filesystem, model, embedding, clock, or mutable global access. It consumes only a validated server-side extracted revision plus a saved explicit review mapping. It does not accept raw SQL, caller-authored normalized rows, guessed aliases, or LLM-selected target fields.

A mapping draft should identify the exact extraction table and header/data ranges; each target field's source column (or explicit constant/system-owned source), and any named, versioned conversion the reviewer selected. It must represent header exclusion explicitly. Support one-to-many rows only when the reviewer maps each field/source deliberately; do not use fuzzy header matching or Thai labels as type evidence. Reject duplicate target mappings, missing mapped required fields once those are specified, out-of-range coordinates, uneven/sparse rows, unresolved formulas, ambiguous merged cells, unsupported multi-row headers, invalid transforms, or any attempt to fabricate blank cells. An empty source cell remains `""` until an explicitly approved nullable/empty conversion rule handles it.

The source-coordinate identity should bind `(jobId, sourceChecksum, jobRevision, extractionRevision, reviewRevision, dataset, tableIndex, headerRowIndex, sourceRowOffset, originalRowOrdinal, sourceColumnIndex, targetField, transformVersion)`. Preserve table `firstRow` and use original ordinals; do not renumber a later noncontiguous PDF table fragment as if its rows were adjacent. PDF/DOCX locations currently prove page/block/table, not physical cell geometry. Any per-cell coordinate reported for those formats must be labeled as parser logical row/column within that located table, never as a visually verified PDF cell. XLSX/CSV have row/column ranges, but the mapper must still preserve exact selected coordinates. A missing or malformed source location blocks structured publication.

Canonical digest input should bind the source checksum and complete review tuple above, registry/schema/mapping versions, selected mapping/transforms, exact typed row payloads and ordered per-cell source map. Root should specify canonical serialization and digest version; output submitted by browser or model is never authoritative. At approval, reload current extraction/review/source, revalidate the saved mapping, recompute rows and digest outside SQL, compare the full binding and saved digest, then pass the prepared immutable result to the final lock/transaction path. A changed source, extraction, review, schema, mapping, or row payload invalidates approval.

**Provenance gap requiring a schema decision:** `SourceLocation` and `knowledge_chunks.source_locations` are document/chunk-level. They cannot by themselves identify which structured row/cell supported an exact fee, date, course code, or form field. In addition, `university_systems` has no document link. Before claiming row-level citations, decide a bounded row-provenance representation (for example, a companion provenance relation tied to document and dataset row, or a reviewed versioned source-coordinate JSON column) and give it RLS, retention, and integrity rules. Do not add an unreviewed generic provenance table by assumption. Citation must be generated only from this stored, publication-bound map and the exact versioned source; it must not invent a page number or link.

The current import review schema is strict v1/v2 and publication's validated path currently expects saved v2 plus a located chunk-plan digest. Preserve frozen v1/v2 parsing/replay. Proposed safe extension is a new schema version for mapping consent (or an explicitly reviewed compatible extension), with RAG v2 receipts unchanged. A structured/BOTH draft must bind mapping digest and mapping revision to job/extraction/review, current dataset registry version, chunk-plan digest when BOTH, and all existing attestations/warnings. Do not mutate historic encrypted receipts in place. The exact schema-version decision belongs to root.

## Publication modes and transaction boundary

- **RAG:** keep current accepted M7/PUB behavior unchanged. Require a valid current chunk plan and all existing review/privacy/version gates. Do not run a structured mapper merely because a candidate table exists.
- **STRUCTURED:** require explicit mode/dataset, installed fixed schema, complete saved mapping, cell provenance, metadata/version/action/target fences, and all applicable warnings resolved. Persist the approved document/version, structured rows, row provenance, activity, and immutable completion receipt in one short transaction. Whether STRUCTURED also persists RAG chunks is not specified consistently enough to decide from the current sources; master §50 lists chunks and then structured rows if needed, while the product mode names imply structured-only. Root must choose and record the exact mode behavior before implementation.
- **BOTH:** require both independently validated chunk plan and structured mapping for the same source/review/document version. Insert both representations, provenance, version/relationship, activity, and receipt atomically; any failed insert/constraint/receipt rolls the entire operation back. Never publish just RAG after structured failure, or vice versa.

For each mode, all parsing, mapping, type validation, coordinate construction, E5/vector work, and external fetches finish before acquiring business locks. The final transaction reauthorizes the active publisher; rechecks job, source checksum, extraction/review counters, mapping/chunk digests, target revision and family/stream applicability; acquires documented sorted family/document locks and existing delivery/family fence; applies the five actions plus whole-document CANCELS semantics; inserts new version/rows/chunks/relationship/audit/receipt; and commits. No delete/backfill of history. Failure leaves no partial live document, chunks, rows, provenance, relationship, activity, or receipt. Exact same-bound retry returns the immutable prior receipt without repeating mapping/provider/network work; stale or changed bindings conflict. Do not broaden `REPLACE_CURRENT`, `AMEND_EXISTING`, `ADD_ADDITIONAL`, `ADD_HISTORICAL`, or `NEW_FAMILY` semantics to fit data convenience. Dataset rows that represent current state must derive their state from the same published document version and explicit action rules, never from an unchecked source flag.

A second schema inconsistency is the `university_services`, `university_systems`, and `service_forms` `active` fields: the source does not say whether these are human-reviewed facts, operational toggles, or computed from current document/version status. Root should decide ownership and historic visibility separately. For source-backed rows, filtering a stale record by `active=true` alone would still leak superseded guidance.

## Fixed structured search, scope and proof

The existing `search_structured` tool already restricts `dataset` to the seven codes and accepts `query` plus the same strict `KnowledgeScope` used by RAG. The implementation must remain backend-owned, fixed-query SQL per registry dataset, with parameterized values only. No model-supplied SQL/table/column/order expression, no arbitrary filters, and no fallback to a similarly named unknown dataset. Since the current free-text `query` does not define exact structured query semantics, root must choose a safe query DSL or add a strict typed filter union per dataset. Avoid implementing fuzzy string search where the user requested an exact fee/date/code. For exact lookups, require explicit field/operator allowlists and bound values; ambiguous or missing dimensions return a safe clarification/incomplete status.

Eligibility must happen before rank/limit: approved and official source; extraction/applicability reviewed; no unresolved `requires_review`; visibility allowed for actor; not archive-only; current/effective/as-of status; family/year/department/audience/student type/semester/program/curriculum/cohort scope; and action/relationship rules. Current student AI has verified LINE session/conversation revision but no authenticated staff role/dept principal in `ToolContext`; therefore the initial `search_structured` tool must return only reviewed PUBLIC rows unless a separate trusted staff authorization contract is added. INTERNAL/RESTRICTED data must not become accessible merely because the model supplied a department code. No student profiles, identity/grade/enrollment datasets, or private ticket data are in this registry.

Default current lookup should use approved `ACTIVE` rows whose owning document is current and within effective dates, with the same statement-stable Bangkok evaluation date used throughout eligibility/proof. Historical lookup requires explicit historical year/as-of scope and returns retained eligible versions only; it does not silently mix old/current rows. Authority then department relevance and exact field-match/relevance, then freshness must be a documented ordering; semantic similarity alone must not select contradictory rules. Family grouping and complete AMENDS/CANCELS logic must match current RAG `searchKnowledge` eligibility. If an amendment or cancellation chain, scope, schema link, or group is unsupported/ambiguous, return bounded `CONTEXT_INCOMPLETE`/clarification, not an arbitrary winner. Existing `buildRuleProof` canonicalizes family/base/version stream/revision/date/member revisions/effects; structured evidence should bind the same proof plus dataset row IDs/revisions/payload digest/source cell coordinates and registry/query version. Recheck that proof and evidence against database state before dispatch; preserve the existing citation/delivery equality and pending-job invalidation fences.

Every exact result should carry server-owned document/version identity, dataset and row identity, approved metadata, current/effective/authority context, safe verified official source reference, and stored row/cell coordinates. Reuse citation safety and strict source-location equality; do not allow the model to write citations or transform exact decimals/dates. If proof/citation evidence is missing or stale, suppress the answer or ask for clarification instead of sending it.

Unknown/uninstalled schema remains fixed-code `STRUCTURED_SEARCH_UNAVAILABLE`/clarification, no dynamic migration or inferred schema. RAG-only selection is an explicit reviewed storage mode; M8 must not silently downgrade a saved BOTH/STRUCTURED choice or imply structured exactness from RAG text.

## Decisions to close before implementation

1. Define exact SQL types, nullability/requiredness, length and numeric bounds, enums, date/timezone conventions, uniqueness/conflict keys, indexes, and row lifecycle for all 7 tables. §12 provides names and only limited nullable/jsonb annotations.
2. Resolve version provenance for `university_systems` and optional document links for imported services/forms; specify the row/cell provenance schema and RLS/citation equality.
3. Define whether `active` and `is_current` are system-owned, reviewer-mapped, or operational states; how historical rows are visible and how source rows deactivate without deleting audit history.
4. Define explicit mapping-review UX/schema/version, per-format coordinate behavior, allowed transformations, header/multi-header/merged/sparse/blank/formula rules, and digest canonicalization. Preserve v1/v2 receipt compatibility.
5. Decide whether STRUCTURED writes chunks/vectors, and define the exact RAG/STRUCTURED/BOTH atomic document representation and receipt shape.
6. Define safe query/filter language for all seven schemas, “current” vs historical/as-of semantics, exact-value ranking/ambiguity, actor roles, and how scope is proven for staff; current AI tool context does not establish staff authorization.
7. Define attachment of one document to multiple rows and one row to multiple source documents; decide whether identical source values create duplicates or revision links. No upsert/overwrite may be inferred.
8. Define which schemas are enabled in the first deploy; a fixed seven-code registry can still return unavailable for a not-yet-installed mapper, but partial installation must be visible and fail closed.
