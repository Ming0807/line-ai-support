## Existing coordinates are table-level except for spreadsheet ranges

`SourceLocation` is a format-discriminated **page/block/table or range** record. `LocatedExtraction` stores one location per page/table, not a source reference per cell (`lib/imports/types.ts:11–19,49–50`). `validateLocatedExtraction` checks format/page alignment, `tableIndex === table-array-index + 1`, and for CSV/XLSX checks that a location row span matches `firstRow` and row count and that the column span matches the widest extracted row. It does not prove individual cell coordinates for PDF/DOCX/HTML (`lib/imports/extraction.ts:32–53`). Structured provenance therefore needs a separate typed cell reference; a copied `SourceLocation` alone cannot prove which cell supplied a fee, date, code, or URL.

| Format | Current parser coordinates and exact-value boundary | Mapping consequence |
|---|---|---|
| CSV | One table, `firstRow: 1`, 1-based logical record/column range (`csv-parser.ts:10–48`). Quoted multiline content stays within one record and retains its embedded line breaks; CR/LF outside quotes ends a record. Ragged rows remain ragged and trigger `TABLE_SHAPE_REVIEW`; a short row has no array element for its missing trailing field, while an explicit trailing delimiter produces `""`. Formula-looking prefixes produce `FORMULAS_PRESENT` without evaluation (`:33–40`). | Define record ordinal, 1-based source coordinates versus 0-based extraction indexes, and behavior for a missing array index versus an explicit blank cell. Do not auto-pad or silently coerce either to null. Treat the CSV prefix heuristic separately from an actual spreadsheet formula. |
| XLSX | A sheet becomes one table over the explicit-cell bounding rectangle. `rowStart`/`columnStart` are the minimum discovered worksheet coordinates; gaps are expanded to empty strings, and `firstRow` equals `rowStart` (`xlsx-parser.ts:95–107,128–150`). The workbook relationship order defines `sheetIndex` and table order (covered in `tests/import-xlsx-parser.test.ts:38–45`). Hidden sheet/row/column values are still extracted and marked; formulas emit cached `<v>` values, never formula text/results recomputed; merged cells and date/style semantics get warnings (`:102–123,129–138`). | Bind sheet name **and** index and physical row/column. A sparse hole and explicit empty cell become indistinguishable in the current extraction. Formula cached values are not source formula lexemes; do not map them as reviewed exact values merely because a warning was dispositioned. Define how retained hidden data is handled. Reject ambiguous merge/date/style cases unless the mapping boundary can resolve them without inference. |
| DOCX | Table `tableIndex` and `blockStart/blockEnd` identify a body block; table rows/cells are logical array positions and `firstRow: 1` (`docx-parser.ts:150–168,200`). Deleted/hidden/revision rows are skipped while later rows are appended to a compact `rows` array; row merges/grid-before/grid-after do not get expanded into a canonical grid and produce review/blocking warnings (`:175–200`). Paragraphs in one cell are joined with `\n` (`:190–192`). | The current logical row number after skipped rows may differ from the original `w:tr` ordinal. Table/block coordinates are not measured cell geometry. Either reject mappings for affected tables or add source ordinals/visibility evidence before claiming original-row provenance. Preserve the chosen cell-text join rule as parser semantics. |
| PDF | `pdf-parse` table candidates are copied as strings. `firstRow` is candidate-local `rowIndex + 1`; an empty detector row splits one candidate into separate output tables while preserving each fragment's original candidate offset. `tableIndex` distinguishes fragments/candidates and increments across the extraction. The location contains page/table identity but uses `blockStart:blockEnd = 1`; it has no measured x/y cell geometry (`pdf-parser.ts:37–39,114–159`; regression contract `tests/import-pdf-parser.test.ts:190–206`). | For a logical cell reference, bind page + fragment/table index + `firstRow + rowOffset` + column ordinal. Do not renumber fragments into an adjacent sequence or describe these coordinates as visually measured page cells. An empty detector row is a split/blocking quality event, not an inferred data row. |
| HTML | Table identity uses final source URL, DOM block index, heading path and table index; logical rows start at 1 (`html-parser.ts:87–89,113–147`). Hidden subtrees are omitted from `findRows`; nested tables are separately extracted and the outer table is marked unsupported (`:120–147`). `normalizeText()` replaces NBSP, collapses all whitespace runs and trims before cells reach `LocatedExtraction` (`:51,101`). | Mapping identity yields logical row/column positions only. Hidden-row omissions compact row indexes, and a review disposition cannot reconstruct them. Identity mapping receives normalized DOM text, not the original cell text; it cannot claim byte/whitespace-exact source lexemes. Require an explicit source-text policy or disallow exact fields when this normalization could change their value. |

The top-level acquisition choice `URL` is not a sixth table format. It resolves to one of PDF/DOCX/XLSX/CSV/HTML; `ImportSource` carries the format, checksum and URL provenance (`lib/imports/types.ts:4–6,22–24`; `lib/imports/source.ts:24–45`). A mapping digest should bind the actual format and the exact extraction/source tuple, not treat a URL as a coordinate system.

## Warning, edit, and unmapped-source traps

1. **Warnings are evidence, not repair.** Parser warnings start `UNRESOLVED`; saved v1/v2 review dispositions require a reason but do not alter the extracted values (`review-schema.ts:27–35`; `review-warnings.ts:26–48`; `import-review.ts:63–74`). Publication currently requires all warnings resolved, always rejects `UNSUPPORTED_TABLES`/`ENCRYPTED_SOURCE`, requires edited pages for OCR correction, and fails closed for non-RAG (`publication-contract.ts:43–57,64–80`). The pure mapper must not interpret `CORRECTED` or `FALSE_POSITIVE` as a row/cell mutation or as proof the extraction became complete.

2. **A shared formula code has different meanings.** XLSX reports actual formula cells as `FORMULAS_PRESENT` while storing cached `<v>` data and not the formula lexeme; tests expect a blocking warning/count (`xlsx-parser.ts:110–123`; `tests/import-xlsx-parser.test.ts:16–20`). CSV flags a leading `=`, `+`, `@`, or `-` pattern but preserves the raw text and never evaluates it (`csv-parser.ts:33–40`; `tests/import-csv-parser.test.ts:11–15`). A blanket “warning cleared” path can either accept an XLSX cache as source truth or unnecessarily reject a literal CSV label. Mapping eligibility must branch on proven format/source semantics and not depend on the warning code alone.

3. **Some parser omissions are not represented as rows.** DOCX skips changed/hidden rows with a table-level blocking warning; HTML omits hidden row subtrees and may leave a warning without a row coordinate. Conversely, XLSX includes hidden values with a warning. PDF detector failure for one page retains other pages/tables but emits blocking `UNSUPPORTED_TABLES`; current publication rejects that source. A mapped-range digest cannot imply full-source coverage from the selected table array alone. For each source table, the design needs an explicit mapped/excluded/rejected disposition, and it must fail where omitted or unsupported source content cannot be enumerated or reconciled.

4. **One candidate is not a complete mapping.** `analyzeExtraction()` picks at most one candidate from the title or first page text, not from all table headers, and the installed dataset list defaults empty. It recommends RAG for an uninstalled schema and can suggest STRUCTURED/BOTH only when its one candidate is installed (`analyzer.ts:7–18,42–56`). The suggestion is not mapping consent. Master §38 allows mixed narrative/table sources to be BOTH; no source authorizes dropping other tables or narrative material silently. A map that selects one dataset/table needs an explicit disposition for every other table/range or a blocking incompleteness result. Header row selection must be reviewer-explicit; there is no header marker in the parser output.

5. **Edits and mappings need the exact same revision tuple.** `applyExtractionEdit()` addresses cells by zero-based table/row/column array indexes and changes extraction data without changing original source bytes/checksum; saving appends a new extraction revision, reruns analysis and makes the previous review stale (`review-draft.ts:4–8,34–63`; `import-extraction.ts:70–85,99–105`; `import-review.ts:26–40`). The current review has an independent append-only revision, while schema v2's optional digest is for the located chunk plan only (`review-schema.ts:21–30`; `publication-contract.ts:59–80`). A prepared mapping must bind the current job ID/revision, original checksum, format/parser and extraction revision, explicit review revision, dataset/registry and mapping versions; any edit or review change must invalidate it. This task does not authorize adding a review-v3 field or publication wiring.

6. **Digest serialization is an engineering contract.** Current warning and chunk-plan hashes use version-tagged JSON material (`review-warnings.ts:26–29`; `located-chunk-plan.ts:468–478`); saved review payload hashes also use `JSON.stringify` (`import-review.ts:73–75`). These are existing local formats, not a general canonical JSON specification. Freeze the mapping digest version and canonical field/row/cell order, string/decimal preservation, transforms/constants, source-cell references, source checksum/format, dataset/registry/mapping versions, extraction and review bindings, and exact typed output. Recompute from validated server-owned extraction and saved explicit mapping. Never hash browser-submitted normalized rows as authority or assume property-order behavior is a permanent cross-version canonicalization standard.

## Open engineering choices for the mapping design

The user/source requirements establish fixed datasets, explicit human review, exact structured use, version/history and fail-closed publication; they do not choose the following details. The design must state them rather than present them as source requirements:

- The meaning of table identity and row/column ordinals in each parser format, including PDF detector-local fragments and DOCX/HTML omitted rows; 0-based extraction indexes versus 1-based displayed/source indexes; inclusive/exclusive range endpoints.
- Whether a map must account for every table and non-table source region, or how explicit reviewer exclusions are represented; how multiple datasets in one original are rejected or separately mapped; header/data ranges and unsupported multi-row headers.
- Per-format decisions for ragged rows, sparse/missing versus explicit blank cells, hidden rows/sheets, formulas/cached results, merged cells, nested tables, parser normalization, and warning disposition. A disposition cannot recreate parser data.
- Allowed named versioned transforms, explicit nullable blank rules, constants, date/year/time-zone and grouped-decimal grammar, exact output lexemes, and transform error policy.
- Versioned canonical mapping/payload digest serialization and complete source/job/extraction/review/registry binding; failure codes must remain sanitized.

The current `review-schema.ts` and `publication-contract.ts` remain strict v1/v2 RAG gates. The pure artifact must be inert: no DB/network/filesystem/model/embedding/clock dependency, no source/browser authority, and no route/tool/review/publication readiness. Broader STR-00/01/02, atomic publication, citations, lifecycle, query and delivery gates remain open.

## 7 October follow-up: Mapping1 design review

**Read:** `docs/architecture/STRUCTURED_MAPPING_DESIGN.md`, `docs/superpowers/plans/2026-10-07-yru-structured-mapping.md`, DEC-039, and the existing parser/validation/test sources cited above. This is an independent source/design review only; no code or other docs changed. The new design correctly makes the mapping a private, pure, exact-source artifact, retains `installed:false`, uses explicit target-field bindings/transforms/constants/ranges/exclusions, computes detached digests, and avoids changing v1/v2/API/publication. Its per-format logical coordinate labels accurately avoid claiming PDF geometry or original DOCX/HTML row indexes.

1. **Blocking format-coverage contradiction: blanket `TABLE_SHAPE_REVIEW` hard-fail rejects every PDF table.** Design §65 rejects any extraction carrying that flag. But `pdf-parser.ts:183–185` adds `TABLE_SHAPE_REVIEW` to every page with a detected table, and even the ordinary table parser test expects that flag (`tests/import-pdf-parser.test.ts:87–93`). Thus an ordinary PDF table cannot produce a Mapping1 plan, despite design §60/plan acceptance expecting all five located formats. The same blanket also rejects XLSX whenever its parser marks row/cell/number formatting (`xlsx-parser.ts:102–123,137–138`). Keep genuinely unrepresentable/unsafe cases fail-closed, but distinguish those from a resolvable human-review warning, or explicitly narrow first-mapper format acceptance and update the plan/matrix claim. `requiresReview:true` and preserved unresolved warnings can keep preparation non-authoritative; a generated plan need not imply the warning was approved.

2. **The “not entirely fabricated” invariant is weaker than its claim.** Design §31 requires one `COLUMN` binding per selected table, but permits binding a nullable field with `blank:'NULL'` while every required/identity field is a constant. A row whose only source column is blank then passes the “at least one column” check and may still validate after the other fields are filled by constants. If the intended invariant is that every emitted row contains a source-backed fact, enforce at least one nonblank source value per row (and consider requiring dataset identity fields to be source-bound); otherwise change the claim and explicitly bound when reviewed constants can stand in for source evidence.

3. **Reconcile row-ordinal acceptance language.** Mapping design §63 correctly says DOCX/HTML row references are extracted logical positions because the parser can omit hidden rows; it must not claim original XML/DOM row ordinals. The broad 6 October M8 plan §36 still says “original row ordinals” for the mapping acceptance. Update that acceptance wording to say physical/logical coordinates per parser evidence, preserving the PDF detector-fragment ordinal but using extracted logical positions for DOCX/HTML. Do not let the pure artifact or its fixture report claim more than the format-specific parser actually retained.

4. **Sparse XLSX semantics intentionally differ from the older rejection gate.** `xlsx-parser.ts:142–149` expands the bounding rectangle and fills absent worksheet coordinates with `''`; `LocatedExtraction` does not retain whether an empty string came from an explicit `<c>` cell or a missing `<c>` element. Mapping design §60 labels the coordinate as a worksheet cell and allows `blank:'NULL'` for nullable targets; the 6 October plan §36 calls for sparse rejection. Decide and document whether an absent worksheet coordinate is acceptable reviewed blank evidence for nullable fields, or reject sparse tables/add occupancy provenance. If accepted, describe `WORKSHEET_CELL` as a grid coordinate whose extracted value may be an implicit blank, and revise the old rejection acceptance rather than claim the parser can distinguish source-cell presence.

5. **Small digest/version clarification:** design names domain-separated payload/mapping/plan digests, but `computeStructuredExtractionDigest()` should also explicitly use a fixed domain tag (for example `structured-extraction-v1`) in the canonical hash input. This prevents its serialization/version contract being implicit while parser/extraction shape evolves.

The design makes important choices explicit that sources leave open: zero-based extraction offsets with inclusive ranges, one dataset per mapping, explicit exclusions/header treatment, named versioned transforms, explicit `+07` offset/midnight conversions without historical IANA claims, canonical JSON/digest domains, size limits, and strict source flags. These are root engineering choices, not original-source requirements. Its source checksum/extraction digest/review counter binding is appropriate for a pure artifact only; the design correctly reserves actual authorization/current-receipt verification for a future server integration. Future review-v3 must bind the saved mapping digest to the exact acknowledgment receipt revision without introducing a self-referential counter; that receipt/publication contract remains deliberately out of scope here.

**Status:** design is substantially source-grounded, but finding 1 blocks the stated all-format first-mapper acceptance until resolved. Findings 2–5 need explicit resolution or plan/design scope adjustment before the implementation report can claim those acceptance points. No mapper code/readiness/M8 acceptance is claimed.
