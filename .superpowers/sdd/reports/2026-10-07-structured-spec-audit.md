## Findings for the current STR-00 draft

1. **Resolve the STRUCTURED vector/chunk conflict before calling the mode contract frozen.** The draft says STRUCTURED publishes rows/provenance without text vectors. DEC-028 and `KNOWLEDGE_IMPORT_DESIGN.md` §Staging and publication say to prepare vectors and structured rows, then atomically publish document/version/chunks/rows/audit/receipt; master §50 lists chunks and embeddings before structured rows. This may be a valid later mode-specific decision, but it conflicts with the existing project decision/design. Record an explicit superseding decision and update the design/plan before implementation. Keep the already settled boundary: all embedding HTTP completes before the publication transaction; only prepared vectors are atomically persisted.

2. **The new exact-row evidence must extend the actual citation and delivery contracts.** `search_structured` currently has a seven-name enum but accepts only free-text `query` plus `KnowledgeScope`; its optional executor is absent, so it fails unavailable. `ToolContext` proves only LINE session, conversation and revision. The current answer schema accepts chunk IDs, `citationEvidenceSchema` is chunk-shaped, and `buildCitedAnswer` constructs URLs/locations only from retrieved chunk evidence. `evidenceStillMatches` and `verifyAIOutboxEvidence` re-fetch RAG evidence and compare that representation. Structured-only rows have no chunk ID to cite. Define a strict structured evidence/citation variant that binds the server-returned row identity, exact typed payload or canonical payload digest, owning document revision, cell coordinates, registry/query version and rule proof; finalization and outbox dispatch must re-query and compare it, including uncited tool context. Model output must select only returned server-owned evidence references; it must never author a fee/date, URL, row identity or citation location.

3. **Row/cell provenance is not present in the current persistence contract.** The parser retains exact string cells and original table `firstRow`; `SourceLocation` and `knowledge_chunks.source_locations` locate chunks/tables, not an exact structured field. XLSX/CSV have physical row/column ranges; PDF/DOCX locations provide page/block/table evidence, not measured cell geometry. The draft's logical PDF/DOCX row/column labels are therefore necessary. Its private provenance relation and document-bound rows close the main gap, including `university_systems` (which has no source `document_id`). Keep each mapping bound to checksum and job/extraction/review revisions, table index, original row ordinal, source column and transform version; never renumber noncontiguous fragments. Specify bounded storage, integrity/FKs, backend read projection, RLS/grants and append-only retention before schema work. Imported service/form rows also need a non-null exact document link even though §12 permits nullable links for other records.

4. **Keep exact-value conversion explicit and lossless.** The sources require exact structured queries but do not prescribe SQL precision, accepted lexemes, currency, date locale/time zone, Thai Buddhist versus Gregorian year conversion, null/blank behavior, or credit rules. The draft correctly labels its numeric/date/string bounds as engineering decisions and rejects implicit currency/year/timezone guesses. Preserve source lexemes alongside exact numeric storage; never pass values through JS floating point or silently trim/normalize identifiers. Before mapper implementation, finish the transform grammar: in particular, “grouped decimal” needs exact separators/grouping validation and no locale inference. Also define date-only versus timestamp conversion, required/nullable field rules and whether invalid rows block the whole publication.

5. **Document lifecycle fields need operational definitions.** The draft makes `is_current` and `active` backend-owned projections, which prevents an uploaded cell from overriding lifecycle. It still needs to state precisely when each becomes true/false for all five actions, historical rows, expiry, amendment instruments and cancellation; and whether `active` duplicates document eligibility or represents a separate reviewed service/form state. Search must join the owning document eligibility even if a row projection is stale. `opening_hours` has only a `jsonb` annotation in §12; storing reviewed source text as a JSON string is a defensible no-invention choice, but the query/output contract must not assume it is an object or silently parse it.

6. **Freeze full mapping and receipt DTOs before v3 review implementation.** Current `review-schema.ts` is a strict encrypted v1/v2 union; v2 binds the located chunk-plan digest. `validatePublicationReview` currently accepts only v2 and RAG; `approveImport` prepares E5 outside SQL then atomically writes the document, relation, chunks, activity, immutable receipt and completion. Preserve v1/v2 and receipt replay unchanged. The design's schema3 sketch currently contains `...explicitReviewedBindings`; specify exact table/ranges, header/data row selection, required-field/constant/source-column mapping, transform identifiers/versions, row-error policy, digest canonical serialization/version, registry/schema versions, and what a receipt binds for RAG/STRUCTURED/BOTH. Browser-normalized rows are never authoritative; approval must recompute mapping and digest from the current saved revisions outside SQL, then recheck those bindings under the final locks.

7. **Use a typed query union and fail on incomplete result groups.** The current tool's `query` is just 1–2000 characters; there is no exact query language. The draft's per-dataset allowlisted filters, exact decimal strings, explicit current/history/as-of scope, clarification for missing dimensions and no semantic approximation fit the requirement. Complete the DTO per dataset and distinguish required identity dimensions from optional filters. Eligibility must run before ranking/limit. If capped results could omit another current row/amendment or a contradictory exact value, return an explicit incomplete/overflow status rather than selecting a winner from the first N rows. Reuse statement-stable Bangkok evaluation date and family/member/effect proof rules from `searchKnowledge`; do not let a supplied department code prove staff authorization. Until a trusted staff principal/scope exists, the student tool path can return PUBLIC rows only.

8. **Be explicit about one source containing several dataset types.** Current `ImportAnalysis.datasetCandidate` and saved review `datasetType` are singular; the design's Mapping1 selects one dataset. Master allows a document to be STRUCTURED or BOTH but does not specify whether one import can map several dataset schemas. If V1 intentionally limits an import to one dataset, surface unmapped/other candidate tables as blockers or explicit review dispositions so the mapper cannot silently drop them. The same applies to duplicate rows: no upsert key or overwrite semantics are source-approved; retained source rows should remain distinct until a reviewed deduplication policy is defined.

## Engineering choices still to close (not missing user requirements)

The following details are not fixed by the original source/master and must remain labelled as root engineering decisions: exact SQL types/nullability/required fields and indexes for each dataset; year/date/timezone and decimal grammar; maximum lengths, enums and code/URL/email policies; row uniqueness and duplicate behavior; whether `active` is a source state, operational state or document projection; query filter grammar and exact ranking/ambiguity rules; whether one import can populate multiple datasets; STRUCTURED chunk/vector semantics; mapping-v3/receipt canonicalization; row-provenance storage/read permissions and retention; and which of the seven mappers are installed at first deployment. The design can choose these within the fixed seven-table, no-per-document-DDL, explicit-review and fail-closed boundaries, but must document each choice and any superseded decision.

The current test at `tests/structured-payload.test.ts:86–96` rejects lone high/low surrogates and malformed sequences while retaining a valid supplementary character.
