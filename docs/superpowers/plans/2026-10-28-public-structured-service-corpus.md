## Audit and chosen design

Initial read-only DEVELOPMENT audit at aa725cd found15 published PUBLIC sources but zero rows in all seven typed datasets. Most sources have no parser tables. HTML sources carry retained hidden-content warnings and the mapper correctly refuses them. Schema4 reviewed-current sources are currently RAG-only; schema4 mapping acknowledgment is not re-prepared on save. Raising limits, deleting parser warnings, synthesizing original tables or inventing effective dates would not solve these problems safely.

Three options: (1) keep RAG only: no typed services directory; (2) build a new text-span Mapping2/provenance protocol: substantial extra contract/migration/UI work; (3) use explicitly labelled manually reviewed CSV transcriptions and the existing Mapping1 uploader. Select3 for this bounded dataset work. It is an uploaded review artifact, never an original CSV fetched from YRU. Retain the official original in existing private storage; retain source URL, original SHA, published document/job identity and exact source block coordinates in the CSV and local review manifest. Every typed value must be checked against the actual source; assigned service codes are explicitly reviewer-assigned catalog labels, not purported official codes. No hidden/comment values or obfuscated email placeholders are transcribed.

Independent Luna max review confirms uploaded CSV may carry a reviewed reference URL, but a CSV checksum alone does not prove its parent. Narrow the first execution to GUIDE→university_services, exactly one CSV data row, an explicit reviewer-assigned service-code constant, and nullable unknown email. Other proposed service/system/form pairs remain future scope. Require a receipt-bound parent-source manifest in schema4: parent document/family/revision, original job/checksum and published extraction/review tuple, official URL, plus exact HTML block and string ranges for each transcribed field. For nonnull source-valued fields, derive the value from those ranges; the URL equals the verified parent URL. Keep the CSV row location separately. Parent metadata/approval/current state and receipt must be re-read at save/publication/search/finalization/delivery; include its digest and parent identity in structured row references and both family/document delivery locks. No permission derives from a caller-supplied ID. Private inherited metadata/hidden blocks/unpublished blocks, unknown or modified parents, and mismatched transcribed values fail closed.

RAG behavior remains compatible. CURRENT_REVIEWED still requires null effective dates, a deliberate reason, NEW_FAMILY/ADD_ADDITIONAL and no relationship/target. Fees, course equivalences, regulations, calendars and announcements get no new typed undated permission. Existing current-only version refresh is not solved here; revoking/changing the parent makes the dependent row ineligible. Keep all existing privacy/sensitivity, unsupported-table/diagram, source, acknowledgment, authorization, revision, lifecycle and delivery fences. Reuse existing encrypted review/receipt, fixed tables, Mapping1 and DB temporal selection: no migration or new infrastructure.
