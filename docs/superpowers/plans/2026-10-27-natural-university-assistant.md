## Verified current starting point

Student durable webhook verifies before parsing, persists inbox events and returns; workers own subsequent conversation/AI/delivery. Configured assistant proposes GENERAL, LOOKUP, MIXED and HANDOFF actions through the existing gateway. Backend validates conversation ownership, source scope, evidence, support confirmation and HUMAN state. General requests may be answered conversationally; university facts require eligible source evidence. This is an implementation description, not proof that every real conversation is natural or complete. Current mixed-answer history includes a known independently useful-general-part gap (DEC167); preserve its actual verdict.

Local cached multilingual E5 creates query/passages vectors and Supabase/Postgres searches approved/current/applicable source chunks. Structured search is a separate path; receipt-backed RAG documents do not populate the seven structured datasets. A constrained, configured web fallback exists for certain knowledge misses, subject to its authorization/allowlist/quota and fresh-source guards. Availability must be verified, not assumed; arbitrary internet browsing is not currently promised. Student AI calls the provider gateway directly; Hermes is currently a staff-only, explicitly requested draft aid with backend knowledge tool, staff authorization, revision/source revalidation and human review. It is not in the Student answering path and is not evidence of better answers without comparative evaluation.

### ROOT-NATURAL-01A initial code inventory — 27 October

- `scripts/local/config.mjs` sets durable webhook mode and **forces web search off** for the local session. `local:ai` sets natural assistant on; `scripts/ai-worker.ts` passes only that assistant flag to configured producer, so optional `scopeFirst`, `evidenceFirstMixed` and `ragCoverage` candidates are not enabled by that worker. A separately running session or deployed configuration has not been inspected here. The existence of web fallback code does not mean the user's local assistant currently searches the web.
- Official retrieval is `configured.ts` → bounded backend tool → scope/applicability-filtered `searchKnowledge`; after model generation `run-worker.ts` rechecks evidence and ownership before durable outbox. External web fallback is limited to eligible evidence misses and has owned-job/proof/quota checks; it currently returns sourced leads and is not a general open-web chat search. Review any future generalized search separately for freshness, source provenance, privacy, free-tier cost and reliable answer synthesis.
- `lineMessages` already splits text by Thai grapheme boundaries into up to five messages of at most5000 UTF-16 units each, preserving concatenation; the schema caps general replies at20000 and RAG prose at12000, and exceptionally oversized packets get an explicit limitation rather than a truncated answer. Future work should test end-to-end delivery/order and improve experience for real limits, not reimplement an existing splitter or claim unlimited messages.
- `createConversationReply` screens model claims with conservative lexical rules; this protects against certain unsupported institutional/action claims but can both reject useful text and miss semantic errors. Historical mixed-question A10 remains a known usefulness failure; no model inference or new quality claim follows from this static inventory.

### ROOT-NATURAL-02 — retain official lookup when a mixed repair fails

Observed code path: default configured orchestrator first rejects unsafe `MIXED_REPLY` prose and calls a bounded repair; a rejected/failed repair currently escapes to the outer catch and drops the independent official lookup. A non-MIXED repair also returns a generic failure without looking up the original official question. Captured A10 repeat transcripts used an optional scoped candidate, so they do not establish that this defect caused those historical outcomes. This is a separately reproducible robustness gap; fixing it does not establish general-answer usefulness or model qualification.

Owner root; requirements CH009–012/035–050/061–064; dependency existing DEC153/167, source ownership, history, attempt budget and recipient guards. Files `lib/ai/assistant-orchestrator.ts`, `tests/assistant-orchestrator.test.ts`, `tests/database/assistant-grounding.integration.ts`, this plan, decision/task/requirements updates. Design: retain the initial mixed decision only as the existing untrusted retrieval hint; if repair errors or returns a different action, call the original source-bound lookup once and deliver the already established partial-general disclosure with its normal official result. Never expose rejected prose, trust it as scope, create a ticket or add retries. Cancellation, including typed `CANCELLED`, must propagate without delivery or lookup. Successful valid repairs retain existing behavior; lookup failure remains honest partial. For GENERAL/CLARIFY repair failures preserve current behavior. RED-first focused tests for repair error, invalid action, cancellation and no leaked rejected text, then focused existing suites/type/lint and appropriate full checks. Mock evidence is not a live Gemini/LINE pass.

## Product value

One LINE conversation combines broad help with the university's reviewed, applicable sources and a human handoff that carries context. Scope-aware citations, staff continuity, local operations and institution-specific workflows are the differentiators; no claim of broad web access, complete YRU coverage or ChatGPT/Gemini-level quality is made until demonstrated. User-specific records stay unavailable without an explicitly designed authorized integration.
