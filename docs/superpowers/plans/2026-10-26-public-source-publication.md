**Goal:** publish reviewed public sources without invented dates and permit accountable adjudication of blank templates and institutional contact findings.

**Architecture:** additive review schema4, preserving byte-canonical schemas1–3. A saved `publicSourceReview` records temporal basis and category-specific sensitivity reasons inside the existing encrypted/revisioned source-bound receipt. Existing normal approval creates documents/chunks and an immutable receipt; no direct SQL publication. Add one feature migration, never one migration per document.

**Alternatives considered:** fake collection-date-as-effective-date corrupts history; removing date/sensitivity checks globally weakens all existing imports. Chosen explicit CURRENT_REVIEWED mode admits only standalone public RAG FORM/GUIDE/CALENDAR, with unknown dates retained, a server-stamped review observation, and no historical/as-of eligibility. DATED schema4 may have unknown publication date but still requires explicit effectiveFrom. Existing schemas keep their exact contract. AMENDS/CANCELS and historical additions require explicit dates; no undated rule effects.

## Contract and invariants

- Schema4 extends schema3 with `publicSourceReview: {temporalBasis:'DATED'|'CURRENT_REVIEWED',temporalReason:string|null,sensitivityAdjudications:[{category:'GRADES'|'STUDENT_RECORDS'|'PHONE',basis:'GENERAL_POLICY_WORDING'|'PUBLIC_BLANK_TEMPLATE'|'INSTITUTIONAL_CONTACT',reason:string}]}`. Max3 unique categories and reason500 chars. It is a public RAG-only feature in this slice; existing STRUCTURED/BOTH contracts remain unchanged and tracked separately.
- CURRENT_REVIEWED requires null effectiveFrom/effectiveTo, nonblank temporalReason, official exact staged source, five attestations, no relationship/historical action and truthful FORM/GUIDE/CALENDAR. Source publishedAt may remain null. DB stores temporal_basis and server current_reviewed_at separately. Neither review time nor signature/filename dates are relabeled as source effective dates.
- All detected categories must have exact matching adjudications and sensitivity warnings FALSE_POSITIVE/nonblank reason. Allow GRADES/policy wording in policy/calendar/guide; STUDENT_RECORDS or GRADES/blank template only for FORM; PHONE/office contact only for GUIDE and public landline contact. Reject unsupported categories, personal mobile/filled identifiers or grade-value patterns; human source-wide inspection remains accountable judgment, not machine proof of absence. Detector output stays intact.
- Existing source/review hash, extraction/job revisions, exact chunk acknowledgment, final actor/family/document locks and delivery rule revisions remain authoritative. A content edit invalidates prior attestations/review under the existing revision model. No arbitrary URL/category override and no new model/LINE calls.
- Current-reviewed CALENDAR must state its source academicYear (policy+DB). Yearless FORM/GUIDE deliberately retain existing global-null scope matching for current queries (for example current library hours even when a conversation mentions2569); this is not evidence about an earlier year, and all historical/as-of queries still exclude them. Shared selection additionally requires a normal RAG publication receipt.
