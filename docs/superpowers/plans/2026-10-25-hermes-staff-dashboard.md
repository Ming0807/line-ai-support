## Design and ownership

Root owns API contracts, authorization/source freshness, integration and acceptance. Luna high owns only the new panel/controller/tests and scoped CSS; Luna max owns only a reusable native runtime/controlled runtime tests. Use existing staff snapshot, knowledge assistance, pinned FREE_ONLY gateway, and ephemeral authenticated loopback bridge. No new database schema, provider, key, message send or publication.

The authenticated POST /api/tickets/[id]/copilot accepts only {revision}. Server derives actor/case/question; it validates the HUMAN case before any model/process work and after completion. Knowledge lookups capture a server-only revalidation receipt so sources and staff scope are rechecked after Hermes drafts, without another generation call. Renderer appends only complete backend source references; model draft body may not invent URLs. All output is ephemeral, unreviewed and bound to ticketId/revision.

Hermes runs from the already-installed private local cache through a native Node adapter; no automatic install/download. Python has one read-only backend tool, a stripped environment and an ephemeral loopback token, never provider keys. Request cancellation/deadline kills only the owned tree. Per-process admission: at most2native jobs, at most1peractor; busy requests fail safely instead of spawning a queue. This is a local/native-host feature; missing runtime returns503, with no plain-model imitation of Hermes. Serverless deployment is not claimed.

Browser response schema: {ticketId,revision,status:'DRAFT',draftText(max12000),evidenceText(max3000),sources(1..5)} or status NOT_VERIFIED/NO_USER_QUESTION with draftText:null and sources:[], evidenceText fixed limitation or null. Staff can inspect/edit/copy into the existing reply composer; no automatic send. Whole draft >5000 cannot be applied to the composer until edited; never slice. Stale/cancelled requests cannot populate another case. Preserve existing unsent text and confirmation before replacement.
