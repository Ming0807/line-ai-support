## PRV-04C — Retry evidence and durable cooldown

Requirements: USR-STATUS/QUOTA/ORDER/TEST; CH014/015/029. Depends on persisted observations and selected probes. Files: `lib/ai/retry-evidence.ts`, shared AI/embedding/observation/provider DTOs, adapters, gateways/store/admin/preview/probe, CLI-generated additive migration, `tests/retry-evidence.test.ts`, cooldown gateway/preview tests and actualPG `tests/database/provider-cooldown.integration.ts`.

1. RED fixtures for actual Retry-After seconds/date; reject invalid/negative/overflow/stale/unbounded hints. HTTP429 alone never proves remaining/exhaustion or a reset time. Honor bounded hints only for rate-limit/5xx outcomes; no invented vendor counters.
2. Preserve normalized retry evidence through adapter/gateway errors. Persist model cooldown with the exact endpoint/key/model identity that produced it; never serialize raw headers/error bodies/credentials. A pending hint uses the time at receipt, so later persistence does not restart the provider's wait.
3. Add separate internal network revisions for provider credentials/endpoint and model identity/purpose/vector dimensions. Normal ordering/display/capability revisions do not erase a real cooldown. Key/platform/model identity changes invalidate old cooldown evidence without deleting observation history. CLI migration defaults preserve existing records/keys. Snapshot fields, parent-first locks and revision guards protect responses arriving during edits.
4. Both runtime gateways skip active matching cooldowns before pricing/decrypt/inference; the saved-order preview uses the same filter and shows COOLDOWN with its real expiry. Leases and manual application throttling remain separate from upstream cooldown. Metadata refresh is not inference proof or permission to clear it.
5. Selected inference tests obey cooldown and record a normalized blocked result without fallback or paid calls. UI shows remaining wait/expiry using data from the backend; when no Retry-After exists, show the actual429 and UNKNOWN timing. No automatic inference polling.
6. GREEN: actualPG rate hint→stored cooldown→reorder retains it→runtime skips it→expiry permits it; key/model changes and in-flight stale identity cannot apply the old hint; generation/embedding/purpose isolation; fixed timestamps/deadlines; role/RLS/private grants. Required regression/type/lint/build afterward.

## PRV-02C — Compatible providers configured through the UI

Requirements: USR-UI/FREE; CH014/029/030. Depends on cost policy, registry and ordering. Files: compatible provider schemas/admin/migration/registry/protocol factory, bounded network module and tests, provider forms, actualPG compatible config tests and browser extension in existing harness.

1. Permit an explicitly configured standard protocol instance through the UI (initial contract: Chat Completions + strict JSON/tools and embedding endpoints). New protocols still need code. Fixed official Zen/OpenRouter/native OpenAI instances keep their existing immutable endpoints.
2. Custom base URLs require HTTPS, no credentials/query/fragment, normalized path/default port and a valid hostname. Authentication precedes public-DNS validation; DNS/network stays outside transactions. Validate again before each network request, reject private/reserved/mixed answers and pin the connection to a verified public address while retaining hostname certificate verification. Disable redirects and enforce body/response/deadline limits. An arbitrary URL must never become a general proxy.
3. Changing platform/host requires a replacement key and increments network revision. Save reauthorizes/rechecks configuration revisions after DNS validation; test/runtime credentials reach only the validated host. DTOs/logs never expose keys or raw upstream bodies.
4. Generic compatible pricing remains UNKNOWN unless a documented trusted pricing contract is implemented. Default FREE_ONLY therefore blocks inference, including probes. A university may explicitly opt into paid runtime use later through the existing authenticated/audited UI; startup tests never enable or call paid services. Manual zero prices do not grant free eligibility.
5. RED→GREEN: URL/DNS/redirect/TLS/rebinding/address classification, JSON/tools/vector/cancellation, config role/host/key/revisions, unknownFREE inference0, explicit paid policy without actual paid calls, browser configuration persistence/order. Use primary protocol/network references and actual installed APIs before implementing transport.

## PRV-02C execution contracts — 5 October

The [contract review](../../../.superpowers/sdd/reports/prv-compatible-contract-review.md) supplies the exact transport types. Root implements `lib/ai/compatible-network.ts` with `CompatibleTransport.request(baseUrl, request)` and `createPinnedHttpsRequest()`. Allowed request routes are only `models` GET, `chat/completions` POST and `embeddings` POST. The request carries a key, abort signal and POST JSON. The result is `{status, contentType, retryAfter, json}`; successful bounded JSON is internal-only, non-success bodies are discarded, and normalized errors preserve any actual received status. Resolver and native request seams are backend code injection only, never API/DB fields.
