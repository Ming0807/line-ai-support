LINE ส่งข้อความเข้าระบบเราอย่างไร?

เป้าหมายของขั้นตอนนี้คือ รับข้อมูลจาก LINE และตรวจว่าคำขอนั้นมีลายเซ็นถูกต้อง ยังไม่ต้องตอบด้วย AI หรือบันทึกฐานข้อมูล

นักศึกษาส่ง LINE→LINE ส่ง POST→ตรวจลายเซ็น→อ่าน JSON→ตอบ 200

แปลคำสั่งที่ GPT ให้ทีละข้อ

  1. สร้าง route.ts: ไฟล์ app/api/line/student/webhook/route.ts ทำให้เรามี URL /api/line/student/webhook ฟังก์ชัน POST จะทำงานเมื่อ LINE ส่ง POST มาที่ URL นี้ ที่มา Next.js
  2. อ่าน raw body: รับข้อมูลต้นฉบับมาก่อน ยังไม่ใช้ request.json() เพราะเราจะใช้ข้อมูลชุดนี้ตรวจลายเซ็น
  3. ตรวจ x-line-signature: LINE แนบลายเซ็นมาใน header เราใช้ LINE_STUDENT_CHANNEL_SECRET และ body เดิมคำนวณ HMAC-SHA256 ถ้าตรงกันจึงรับคำขอ ถ้าไม่ตรงตอบ 401 ที่มา LINE
  4. ค่อยแปลง JSON: หลังตรวจผ่าน จึงใช้ JSON.parse อ่าน fields เช่น events
  5. Log payload: ในตัวอย่างพื้นฐาน พิมพ์ข้อมูลที่ตรวจแล้วลง terminal ของ server เพื่อดูว่า LINE ส่งอะไรมา ตัวอย่างนี้ไม่มี AI หรือฐานข้อมูล
  6. ตอบ HTTP 200: แจ้ง LINE ว่าได้รับคำขอแล้ว {"events":[]} ก็เป็นคำขอทดสอบที่ถูกต้องและต้องตอบ 200 เมื่อมีลายเซ็นถูกต้อง ที่มา LINE

Channel Secret นี้มาจาก LINE Developers ของ OA นักศึกษา เป็นคนละค่ากับ Supabase key และ SSH public key

ทำไมต้องตรวจ body ก่อนแปลง JSON?

{"events":[]}
{ "events": [] }

สองบรรทัดนี้แปลงเป็น object เดียวกันได้ แต่มีช่องว่างต่างกัน จึงเป็นข้อมูลคนละชุดสำหรับการคำนวณลายเซ็น ถ้าเราแปลงแล้วประกอบ JSON ใหม่ก่อนตรวจ อาจทำให้คำขอจริงตรวจไม่ผ่าน

ลองด้วยข้อมูลจำลอง

ลายเซ็นในตัวอย่างสร้างจากบรรทัดแรก กดตรวจ แล้วลองเพิ่มช่องว่าง ค่า secret เป็นค่าจำลองที่ฝังในบทเรียนนี้เท่านั้น

พร้อมทดลอง

HTTP 200 ไม่ได้ส่งข้อความตอบนักศึกษา

200 เป็นคำตอบจาก server ของเราไปยัง server ของ LINE ว่า “รับคำขอแล้ว” การส่งข้อความกลับไปในแชตเป็นงานอีกขั้นหนึ่งผ่าน reply/push API ดังนั้นจบขั้นตอนนี้แล้ว นักศึกษาอาจยังไม่ได้รับข้อความตอบ

ทบทวน: events ว่างควรตอบอะไร?

ถ้าลายเซ็นถูกต้อง ตอบ 200 ได้เลย เป็นการทดสอบ endpoint ไม่ต้องรอให้มีข้อความจริง
