## Decision and scope

Use an authorized read-only family catalog beside the existing private import-job list. A family page exposes paginated approved-version history; a selected document exposes exact metadata and paginated stored relationship links. A single flat document list obscures parallel version streams; embedding-driven selection cannot represent authoritative history. Family summaries plus explicit history preserve the specification's distinctions with bounded queries and existing UI tokens. No graph visualization, mutation controls or model calls are needed.

Preserve current SUPER_ADMIN-only knowledge management. Verified session and active database SUPER_ADMIN precede input parsing/private queries. Other staff and anonymous callers cannot access these management APIs; staff knowledge assistance remains a separate ADV-05 authorized tool. SQL privileges/RLS remain unchanged. No new migration, original decryption, chunk text, storage path/key, vector, review plaintext or credentials enter catalog DTOs. Source URLs are metadata; the catalog never fetches them. Display links only when HTTPS with no credentials; otherwise render plain text.

Select `documents.approval_status='APPROVED'` for published catalog/history; retain every stored lifecycle state and visibility as facts. `is_current` is the stored stream flag, not proof that a rule is effective, PUBLIC or answer-eligible. Show dates/visibility/status separately. Stored relationships are links, not a computed declaration that an amendment is presently applicable. No catalog query changes retrieval or publication state.

Document storageMode comes from its immutable publication receipt. Legacy documents without that receipt return null, labelled as unknown; never substitute family.default_storage_mode. Last import is the linked original import job's created_at; legacy null remains explicit. Family default mode is separately named configuration metadata. Retained historical/source metadata is visible to authorized admin even when not eligible for student answers.

## API and DTO

Root owns browser-safe strict schemas/types in `lib/knowledge/catalog-types.ts`,server service `catalog.ts`,authorization/API/helpers/tests. JSON envelopes contain exactly their indicated root key. Nodes use existing private/no-store/VaryCookie/nosniff headers and sanitized fixed import errors. GET only.

`GET /api/knowledge/catalog`: allowed query keys `q`,`departmentCode`,`status`,`page`,`pageSize`;duplicates/unknown keys invalid. q optional trimmed1..120Unicode characters. departmentCode optional `[A-Z][A-Z0-9_]{1,79}`. status optional exact existing document lifecycle enum. page1..10000/default1;pageSize1..50/default10. Service input is strict corresponding nullable q/departmentCode/status plus numeric page/pageSize. Filtering is literal case-insensitive family code/name or approved-document title,parameterized values. Department/status filters restrict matched documents;without either filter seeded families with zero approved documents remain explicit empty groups. Families sort by code,id;version previews sort stored current first,then effective_from DESC NULLS LAST,created_at DESC,id. Totals and page share one statement snapshot. Each family returns at most5matched version previews,real matched document count and `hasMoreVersions`;history offers all versions. Return `{catalog:{families,departments,totalFamilies,totalDocuments,page,pageSize}}` with actual department code/name options. Out-of-range valid pages return empty with true totals,not fabricated defaults.

`GET /api/knowledge/families/[id]?page=&pageSize=`: active-admin before UUID/query validation;missing family404. Return `{history:{family,documents,totalDocuments,page,pageSize}}`. All approved versions in that family,including parallel streams,old/future/archive and relationship instruments. Stable order:stream ASC,effective_from DESC NULLS LAST,created_at DESC,id. No current-answer selection or source substitution. Bounded history pagination preserves complete access.

`GET /api/knowledge/documents/[id]?relationsPage=&relationsPageSize=`: same preflight;missing/unapproved document404. Return `{document:{summary,scope,review,supersedesDocumentId,createdAt,updatedAt,relationships,totalRelationships,relationsPage,relationsPageSize}}`. Relationship page uses1..10000 and1..50/default25. Only links whose other endpoint is approved are exposed;each has type,direction INCOMING/OUTGOING,related document ID/title/version/status. Sort created_at,id;no hidden truncate. Report true count and pagination.

Family fields: `id,code,name,category,defaultStorageMode`. Summary fields: `id,familyId,title,documentType,versionName,versionStream,academicYear,department:null|{code,name},status,isCurrent,visibility,storageMode:null|RAG|STRUCTURED|BOTH,publishedAt,effectiveFrom,effectiveTo,authorityLevel,approvedAt,sourceUrl,sourcePageUrl,lastImportAt`. Dates are ISO civil dates;timestamps canonical UTC ISO. Scope contains semester,audience,studentType,programCode,curriculumCode,cohort. Review contains officialSource,extractionReviewed,requiresReview,archiveOnly. Exact output whitelist excludes private bodies/hashes/actors. Shared schemas deeply validate response shapes/bounds before browser rendering;cross-family/document results are rejected.

All service queries use the existing active-admin transaction wrapper and bounded statement/lock timeouts. Abort is checked before and after work. No external work in SQL. Catalog counts are administrative inventory counts,not answer-eligibility metrics. Final returned data is independent of subsequent writes;refresh makes that observation explicit.

## UI

Keep current `/knowledge` page auth/breadcrumb/import action and existing import-job section. Add a default-open published catalog above intake. Use minimal searchable family rows/cards with real counts and preview current/status/version/department/mode/dates/source/last import. Explicit history action reveals a labelled inline region with pagination;document action reveals metadata/relationship history in a second region. No nested dialog,hover-only control,auto-select latest ticket or generated content.

Search submits deliberately and resets catalog page. Filter/search drafts are distinct from applied filters. Independent loading/error/retry,empty filtered result and no-approved-version states. Abort/serial fences protect changed selections;old detail may never appear under a new family heading. Accessible headings/focus,live loading,keyboard pagination,status text and responsive wrapping;long URLs/names do not create document-level horizontal overflow. Table internal scrolling may be labelled/focusable. Existing imports/review/approval/LINE routes remain working.
