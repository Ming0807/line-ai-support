## Fixed storage contract

DEC-049 follow-up: [STR-01C-0 row-envelope design](STRUCTURED_ROW_ENVELOPE_DESIGN.md) authorizes an unused authenticated evidence component only. It implements the bounded envelope/AAD prerequisite described below; actual mapper-source-derived persistence, atomic mode receipt/effect proof, installation and live retrieval remain deferred. The envelope itself does not certify approval/currentness or source truth.

Seven exact master table names: academic_calendar_events, tuition_fees, transfer_courses, university_services, university_systems, service_forms, announcements. Every row has backend-owned UUID id, required document_id, generated constant dataset_code, active/is_current lifecycle projections and created_at/updated_at. Services/systems/forms/announcements additionally have nullable department_id equal to the owning document. Required source linkage for services/forms and the additive systems document link are explicit engineering decisions preserving imported version provenance. Source columns/nullability/bounds follow the accepted pure payload contract. opening_hours remains jsonb as in the master, containing a reviewed JSON string or SQL null, not an invented weekly schedule.

Fees and credits use unconstrained numeric with finite nonnegative bounds and scale CHECKs (fees <=9999999999.99 and scale<=2; credits <=999.999 and scale<=3). This supersedes the proposed numeric(12,2)/(6,3) in the earlier payload design: PostgreSQL rounds typmod input before CHECK, which would silently accept excessive scale. Source lexemes remain in private encrypted evidence; canonical lexeme validation remains the existing server validator. Civil dates 1800–2400 and intervals are checked. Announcement timestamps are bounded timestamptz with exact millisecond precision checks; UTC source spelling/timezone conversion remains the server contract. SQL character counts can be broader than JS UTF-16 bounds; server validation remains authoritative. SQL rejects blank/control text and malformed uppercase currency. URL/email canonical validation stays in the existing pure contract, not an invented SQL regex.

SQL validates parsed values, not original spellings: numeric exponent/leading-zero spelling and timestamp offsets or precision below PostgreSQL's representable microsecond resolution cannot be reconstructed from typed columns. The existing strict source payload validator remains mandatory before persistence, and the future authenticated private row envelope retains exact reviewed lexemes. Tests reject representable sub-millisecond timestamps; no claim is made that SQL alone rejects every noncanonical timestamp spelling.

## Private provenance and retention

private.structured_row_provenance is append-only. It stores row/document/dataset identity, publication document revision snapshot, immutable original checksum/format/job identity, saved review/job/extraction revisions, canonical extraction/mapping/payload/plan digests, version1 registry/mapper identifiers and detector table/row coordinates. An opaque bounded evidence_encrypted envelope stores cell bindings, original lexemes, constants, source location and private notes. No plaintext raw cell/URL/note field is exposed. Shape/length checks do not authenticate encryption or prove a reviewed mapping; future publication must recompute and authenticate these bindings outside SQL. Future envelope AAD must domain-separate version, row, document, dataset, job/checksum/revisions and mapping/payload digests; implementation is deferred to atomic persistence, never reuse a job-only envelope for cross-row evidence.

Composite FKs bind provenance to immutable job checksum/format and the exact saved review/job/extraction tuple. Each public row's (id,document_id,generated dataset_code) references that same private tuple. A deferred constraint trigger rejects provenance without its matching typed row at transaction end; insertion of provenance and row is one future backend transaction. Coordinates satisfy source_row=table_first_row+row_index, preserve zero-based detector indices, and distinguish WORKSHEET_CELL/CSV_RECORD/EXTRACTED_LOGICAL. The provenance insert locks its document FOR SHARE and requires matching checksum/revision plus an ACTIVE approved reviewed document. This binds storage identity; the later atomic publication receipt still must prove the job-to-document transaction and canonical hashes.

Payload, identity, department, created timestamp and provenance cannot be updated or deleted through service_role. Public row updates permit only lifecycle projections/time; the trigger derives flags from the owning document rather than trusting caller values. Source mutation/delete triggers also reject owner-level ordinary DML. Document lifecycle updates synchronize all seven fixed tables. A structured-bearing document cannot change checksum/department: publish a new retained version instead. Revision may increase for lifecycle changes; the published revision is a snapshot, not an FK to mutable live revision. The active flag reflects approved ACTIVE document status, not wall-clock interval eligibility; all future queries must join canonical document visibility/current/authority/applicability/effect proof first. Projection flags are never authorization.

## Access and indexes

Concurrency correction verified through an actual two-connection regression: provenance/typed INSERT takes a source share lock; immutable row UPDATE must read the canonical document without taking a second source lock after acquiring its typed-row lock. Otherwise a document lifecycle update holding document then waiting row creates an inverted lock cycle. The waiting lifecycle transaction refreshes flags after the row-only update releases its lock; canonical document eligibility stays authoritative. The generated constant dataset discriminator is computed after BEFORE triggers, so the immutable-source comparison excludes it; PostgreSQL itself rejects supplied values and the FK uses the generated constant. Complete covering composite FK indexes are included after actual isolated advisors identified the initial seven missing coverings.

RLS is enabled on all eight tables. PUBLIC/anon/authenticated have no grants or policies. service_role receives SELECT/INSERT, column UPDATE(active,is_current,updated_at) on typed rows, SELECT/INSERT only on private provenance, and the exact private trigger/helper EXECUTE grants. No client direct read or write, PUBLIC function execute, security definer, HTTP/AI/DDL-from-input or privileged SQL API is introduced. Server-scoped staff/student authorization is deferred to the retrieval/persistence component; denial of browser access is not evidence of that future service authorization.

Constant static SQL only. Index document FKs, four department FKs, review tuple, exact provenance coordinates, and dataset dimensions for future bounded exact predicates. No per-year tables, old-row deletion or ANN/vector changes. Existing RAG publication receipt is unchanged; its later additive mode proof migration is separately gated.

Maximum accepted multibyte labels must fit actual B-tree keys. Fee lookup index uses academic_year/program_name/effective_from and exact remaining dimensions are filter predicates. Transfer indexes use the short source/target code pair plus separate target-code/source-program/target-program indexes, rather than concatenating four wide source labels. This preserves all field bounds and literal matching; it neither truncates source values nor changes equality to a hash comparison. Actual incompressible accepted UTF-16/UTF-8 maximum fixtures exposed the initial overflow and are required to pass after correction. [PostgreSQL B-tree limits](https://www.postgresql.org/docs/17/btree.html).
