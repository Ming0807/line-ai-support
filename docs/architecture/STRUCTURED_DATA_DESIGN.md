## Implementation boundary and chosen approach

Use seven fixed typed tables plus version-bound private row provenance. A generic JSON-only knowledge table would lose the master's exact field/query contracts; tables per year/document would violate versioning. All document changes are data/version updates in fixed schemas. Unknown types remain visibly unavailable for structured storage and may use only deliberately selected RAG. Backend selects constant registry entries; no caller/AI chooses SQL identifiers or executes DDL.

The independent first slice is `lib/knowledge/structured-payload.ts` and `structured-registry.ts`: strict pure validators and allowlisted field metadata, with every entry **installed:false**. This does not change a route, tool, existing review receipt, schema, original or publication. It can be implemented and tested while Gemini owns presentation. The previous gate requiring combined UI integration before **all** M8 code unnecessarily held this inert preparation; only integration/mutation gates remain held. The new decision is recorded in the decision log before implementation.

## Payload vocabulary and exact conversion boundary

Payloads contain only source-valued columns. `id`, `document_id`, `department_id`, `created_at`, `updated_at`, `active`, `is_current`, row provenance and publication identities are backend-owned and rejected as input. All listed source keys are present as own data properties on a plain/null-prototype object; accessors and inherited fields are not source evidence and are rejected without reading them. Optional values are explicit null, never omitted or silently converted from blank strings. The exact own-key set rejects extra keys including hidden/symbol fields. Validation snapshots data descriptors before parsing. Names/labels/code values preserve the exact approved string, including leading zeros and whitespace; non-null strings must contain non-whitespace text and reject control characters U+0000–001F except tab/newline/carriage return and U+007F. Optional empty strings fail; an explicit mapping conversion may choose null later.

Text bounds are JS UTF-16 code units in the pure contract: short labels/codes200, scope strings80, titles/names500, descriptions/conditions/summary/requirements5000, service opening-hours text2000, phone100 and URL2000. Strings must be well-formed UTF-16 (no unpaired surrogates) so UTF-8 persistence cannot replace an accepted source lexeme; reject without Unicode normalization/repair. SQL uses `text` with corresponding safe upper bounds (PostgreSQL character checks may be broader for supplementary characters; server contract stays authoritative). Registry1 rows have no fuzzy code normalization, invented enums or student identity/profile columns.

`academic_year` is an explicit reviewed Thai Buddhist academic year integer2400–3000; no automatic calendar-year inference. Civil dates are valid exact Gregorian `YYYY-MM-DD` in1800–2400; Buddhist text requires a separately selected era conversion. Dates are inclusive, end>=start. `semester`, `student_type`, fee dimensions and course codes are source labels; no undocumented taxonomy is invented.

Exact decimals are strings, not JS numbers. Fees use canonical unsigned decimal lexemes with1–10integer digits and at most2fractional digits, no leading integer zeros except zero, no sign/exponent/grouping/whitespace; preserve fractional zeros. Future SQL `numeric(12,2)` stores exact values, while private provenance keeps the source lexeme for display/audit. Credits use1–3integer digits/at most3fractional digits, future `numeric(6,3)`. Zero is valid, negative/refund amounts are outside registry1 and must fail visibly; do not round excess scale. Currency is exactly3uppercaseASCII letters supplied by the reviewed source/mapping; no implicit THB or asserted verified ISO membership.

Announcement timestamps are canonical UTC `YYYY-MM-DDTHH:mm:ss.sssZ`, valid civil time1800–2400; future SQL `timestamptz`. A source with only a date/local time requires an explicit reviewed `Asia/Bangkok` conversion, never upload time/host timezone. `priority` is a reviewed integer0–100; larger sorts first. Optional email is a single ASCII mailbox with no whitespace/control, max254; URLs are HTTPS with a hostname and no userinfo, explicit port, fragment, whitespace/backslash/control, max2000. Row URLs are inert referenced contact/system links, **not** official document authority and not fetched automatically. Public document authority still requires existing verified official YRU source metadata. Preserve the lexeme, do not normalize/rewrite it.

Required fields are plain; `?` means the key is required but its value may be null. Every field below keeps its exact master§12 name. Backend-owned columns remain part of future tables but outside these payloads.

All seven row IDs are backend UUIDs generated only for finalized publication.

## Future fixed schema, provenance and lifecycle

One additive reviewed migration will create all seven tables plus `private.structured_row_provenance` and mapping receipt support. Preserve source-listed columns; add generated constant `dataset_code` to each table for integrity. The provenance row ID is the typed row ID, with unique `(id, document_id, dataset_code)`; each fixed table has a composite foreign key to that tuple and a non-null document foreign key. This prevents source/document/dataset mismatches without accepting a dynamic table identifier. Runtime grants allow append only to provenance; encrypted imports/reviews/originals and old receipts retain existing no-delete policy. Index all foreign-key/document columns and exact lookup dimensions. No global unique code constraint/upsert destroys historical system/course/service rows.

Provenance binds job/checksum/jobRevision/extractionRevision/reviewRevision/registryVersion/mappingVersion/digest plus typed payload digest, table index and format-specific row coordinate, and every target field's cell/constant evidence. Cell references preserve the stored located table and `firstRow+rowOffset`/column ordinal. Mapping1 labels XLSX grid positions, CSV logical records, PDF detector-local ordinals scoped by page/table and DOCX/HTML extracted logical positions, with no absent-cell occupancy or original DOM/XML/visual geometry claim. Registry row values are immutable; duplicate exact coordinates within a publication fail, while distinct source rows with identical values remain separate observations. One source row belongs to exactly one approved document/version; a later import makes new rows rather than modifying old values.

RLS on all seven public tables and private provenance; no anon/browser direct write or raw provenance exposure. Backend tools execute with verified conversation or active scoped staff authorization, applying document sensitivity/department/current/authority/applicability gates. Student path is PUBLIC-only. SQL grants and policies will be verified with actual roles before acceptance. Stored active/current row flags are backend document lifecycle projections, not source-supplied overrides; history retains all original payload/provenance even after flags change. Public querying always joins owning document eligibility, so stale projections cannot bypass it.

## Reviewed mapping, modes and receipt compatibility

Mapping1 selects one installed dataset and bounded tables/ranges/field bindings with explicit header exclusion. Only named versioned transforms are allowed: identity text, blank-to-null for nullable fields, explicit Gregorian/Buddhist civil date, exact ungrouped/grouped decimal, integerBE, explicit currency code, and timezone conversion. Constants require deliberate review and labelled evidence. No guessed aliases/locale/header/body values, formula evaluation, silently skipped invalid row or default authority. Mapping errors have fixed field/row/code locations, never echoed private cell text in logs. Preview preserves all source values/provenance; every blocking row must be corrected before approval.

New encrypted review schema3 adds `structuredMapping:{version:1,dataset,registryVersion,mappingDigest,...explicitReviewedBindings}` plus a nullable existing chunk-plan acknowledgment. v1/v2 RAG parsing/replay stays intact. Pure payload contract in this first slice does not add schema3 or expose mapping UI. Final mapping preparation reloads verified source/review, recomputes immutable rows/digest outside SQL, and passes only root-owned prepared artifacts to final revision/role/family/target locks.

Modes under explicit DEC-038: RAG retains current chunks/E5/receipt behavior and needs no mapper. STRUCTURED publishes validated typed rows/provenance without chunks/text vectors; BOTH publishes both exact text chunks/E5 and typed rows for the same approved document atomically. The source audit found that DEC-028 and the older generic import effect list could imply vectors in all modes; DEC-038 supersedes that interpretation while preserving outside-SQL preparation and mode-specific atomic persistence. Existing common attestations/warnings/source/privacy/version gates apply to all. Receipt support evolves additively: legacy RAG receipts stay readable; new structured plan proof includes mapping digest/registry/payload digests and an optional chunk digest/fingerprint. No inference/embedding/network inside SQL; no fallback/downgrade from a saved structured choice. Actual rollback/replay/concurrency tests precede enabling installed mode readiness.

## Exact query and amendment safety

Replace the unimplemented free-text search hook only after a strict version1 query union exists. Typed per-dataset allowlisted filters use equality for codes/dimensions, date/time ranges or event date inclusion, and numeric ranges using exact decimal strings. A human question's missing program/year/student-type dimensions returns clarification rather than an arbitrary fee. Student/context identity comes from backend, never tool arguments. Cap result20/proof members200/effects400 under existing bounded5sSQL policy. Filter eligibility before authority/department/exact-match/freshness ranking; no semantic approximation changes exact values.

Base selection/current/history/as-of uses complete existing family/member/effect/date proof. Return all applicable structured observations from base and active amendments with their exact source/member identity; do not overwrite a base cell by heuristic title or row order. If contradictory rows could change the requested answer and no explicitly reviewed supersession/effect resolves them, return `CONTEXT_INCOMPLETE` with safe clarification. CANCELS removes cancelled observations through the same complete rule group; unsupported indirect/scope/effect context fails visibly. Evidence includes dataset/row/payload/mapping/registry/source coordinates plus document revision and existing rule proof. Result/finalization/dispatch must revalidate all of it before delivery, including uncited model context; HUMAN mode remains protected.
