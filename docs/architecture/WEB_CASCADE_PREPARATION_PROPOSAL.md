# ADV-05C-2 — web cascade preparation proposal

> **Status: PROPOSED — NOT ROOT-ACCEPTED.** This is a bounded design for the remaining ADV-05C web slices. It changes no runtime behavior, migration, board status, provider configuration, or acceptance result. Root owns the eventual contract, DB/auth/privacy choices, integration, and acceptance.

Prepared 9 October 2026 for CH032/CH052/USR-WEB and original overview §27. Read with [current source-cascade design](SOURCE_CASCADE_DESIGN.md), [C1 execution plan](../superpowers/plans/2026-10-09-yru-source-cascade.md), [DEC-060](../decisions/DECISION_LOG.md), and the current task board. The earlier bounded-web proposal remains unaccepted; its source ideas are usable only where they match current code and DEC-060. In particular, do not require an approved persistent source row before ephemeral official-page proof.

## Current code boundary

C1 already makes a successful Structured `EMPTY` continue into reviewed RAG and retains the private `structuredMiss` query. `lib/ai/jobs.ts`, `lib/ai/run-worker.ts`, `lib/knowledge/delivery-fence.ts`, `lib/queue/run-outbox.ts`, and `lib/staff/knowledge-assistance.ts` freshly recheck that negative proof using the structured catalog fence. Structured clarification, errors, incomplete reads and unavailable evidence stop. `lib/knowledge/answer-producer.ts` currently returns a clarification when RAG is empty; it has no web adapter or durable, recheckable RAG-miss result. That distinction must be added before an external result can be eligible.

`lib/staff/knowledge-assistance.ts` reuses the pure producer only behind a fresh HUMAN actor/ticket scope snapshot, commits before provider/E5 work, then rechecks actor, source and ticket state. Its advice is projected as editable citations; it never enqueues a reply. Student production goes through the durable AI worker, finalizer and outbound evidence fence. These are separate consumers of the shared result contract.

`lib/imports/url-importer.ts` is for known-URL import and eventual review/publication. It already demonstrates official-host validation, public A/AAAA resolution, pinned HTTPS, redirect revalidation and bounded bodies. Runtime evidence needs its own tighter policy/limits and must reuse only suitable low-level transport/address primitives. Do not invoke import creation or publication from chat search. `lib/ai/compatible-network.ts` and `lib/ai/public-addresses.ts` show the repository's pinned, public-address-only network pattern.

## Proposed behavior and contracts

The backend keeps the order `Structured → reviewed RAG → official YRU → general public`. Only a complete `MISS` or an explicitly validated `NOT_APPLICABLE` advances. `CLARIFY`, unauthorized, conflict, stale, `CONTEXT_INCOMPLETE`, malformed result, timeout, exception and provider failure stop with a truthful limitation. A valid empty Tavily response is a completed external search with no results; HTTP errors, timeout, truncated body and malformed JSON are unavailable, never a miss.

Add an explicit private result for completed web evidence (suggested `WEB_ANSWER`/`WEB_LEAD`), rather than making a clarification look like a search result. It carries: validated intent/purpose and topic code; the private structured miss or validated not-applicable proof; the local E5 query-vector fingerprint and a private RAG-miss marker; opaque server-issued source IDs; bounded citations; provider attempt ID/usage observation; and, for an official page, an ephemeral page proof. The schema is strict, size-limited and encrypted with the existing job result. It contains no student/case text or identifier in the provider request, citation projection, or logs. Raw page bodies are discarded after hashing and extracting the exact proof spans. Do not add persistent knowledge rows or auto-approve/import a page. Root must set and implement result/outbox retention: retain the minimum encrypted evidence only until the final Student delivery check or Staff projection is complete, then clear it at the earliest safe existing lifecycle point. Current job results otherwise persist, so “ephemeral” must not be left as an undocumented promise.

The model may choose only a fixed `topicCode` and a strict intent enum from a backend-owned vocabulary. Backend validation may accept explicit public selectors, such as a clearly stated year, only when they are already grounded and permitted by that topic. The provider query is constructed from those public tokens, never raw ticket text, history, summaries, names, student IDs, LINE identities, private source passages, ticket/conversation/message IDs or a model-supplied URL. No general arbitrary-text search in the first slice. Ambiguous intent defaults to YRU policy and does not open the general tier. `GENERAL_PUBLIC` may retrieve separately labeled public context but can never answer a YRU policy claim.

A successful generation-provider `FREE_ONLY` check is not a search billing check. Tavily is only a conditional adapter candidate. Its official pricing page currently lists 1,000 free Researcher credits/month, says requests stop at exhaustion until reset or upgrade, and separately lists Pay As You Go at $0.008/credit ([pricing](https://www.tavily.com/pricing)). The Search API is a fixed Bearer-authenticated `POST /search`, supports restrictive `include_domains_mode`, returns usage/request ID and documents 432 plan-limit and 433 Pay-As-You-Go-limit responses ([Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)). Its `/usage` endpoint exposes key/account usage and plan fields, but documents no atomic reservation; a read is observability, not authorization for the next billable request ([Usage API](https://docs.tavily.com/documentation/api-reference/endpoint/usage)). The privacy policy says query data may be used to improve later responses and may be shared with third-party search indexes when needed ([Privacy Policy](https://www.tavily.com/privacy)); minimization is therefore required.

Search is enabled only when the secret exists **and** the configured provider account is positively attested as the free Researcher plan with Pay As You Go disabled and no automatic paid upgrade/fallback. The provider account/key owner must control that account setting; an absent, stale, conflicting or unknown attestation yields `FREE_ONLY_UNVERIFIABLE` and zero outbound HTTP. Check any configured identity/plan evidence for the expected Researcher plan; missing/unknown fields fail closed. `/usage` may support operator observation, but neither a preflight usage read nor app-local counters prove shared account state. The provider's own free-tier hard stop is the useful no-charge property; if the account changes to a plan or setting where that hard stop cannot be relied on, the adapter is disabled. Do not claim the app can technically prevent an account owner from changing a vendor setting after attestation.

Before each actual search HTTP call, reserve the selected application quota in one atomic DB transaction and commit it. The reservation is unique to the durable AI job and purpose/tier. A committed reservation is consumed even if the process crashes before/while sending, the response times out, or usage is unknown. Never refund an uncertain attempt; never retry it on worker takeover; never call a paid or unknown fallback. A missing key/config, unverifiable plan, duplicate consumed reservation or exhausted local budget makes zero search HTTP calls. Numeric monthly/daily caps are deliberately **not selected here**; root must choose them before implementing the reservation table/function. Any vendor 432/433, 429, non-2xx, timeout, abort, malformed/oversize response or bad usage shape is an unavailable search and cannot trigger retry/fallback. Usage and safe request ID/status/latency observations must not contain keys, queries, ticket facts, response bodies or provider prompts.

For official YRU evidence, search results only propose candidates. The server parses candidate URLs and requires HTTPS, no userinfo/unexpected port/IP literal, canonical allowed host, and a configured `topicCode + host/path → issuing office/source class` mapping. Provider domain filtering is defense in depth, not a trust decision. Runtime fetch uses the repository's pinned public-DNS/TLS pattern, revalidates every redirect against that exact configured scope, sends no cookies/auth, bounds response bytes/time, and hashes decoded page bytes. Generic result URLs are not fetched server-side in the initial slice.

An official host alone is not proof of policy. The pure validator must require exact page evidence for the configured issuing office and source class, explicit current/effective status at the request's `asOf`, applicable audience/program/department/year, and a complete applicable amendment/cancellation chain. A source-scope registry is server configuration, not a database publication or approval record. A page can produce `VERIFIED_EPHEMERAL_YRU_POLICY` only when the page or its explicitly linked authoritative current-consolidated source establishes all required fields and the proof digest still matches. An update timestamp, search-result rank, provider date, domain name, or absence of a later search hit does not prove currentness or no amendment. If a bounded official lookup cannot establish one field or resolve a conflict, return a useful cited `YRU_SOURCE_LEAD`/clarification with the missing fact named; do not claim a verified policy answer. This gives a working route for mapped official pages with explicit proof while being candid that many ordinary web pages will remain leads until source metadata supports a safe proof.

## Delivery and Staff fences

For Student delivery, first recheck internal Structured miss and RAG miss under the existing catalog-first source fence. For web proof, do not do HTTP in SQL. Load the durable result and dispatch snapshot, commit, refresh an aged official page proof through bounded HTTP outside SQL, then enter the short delivery lock and compare conversation revision, job/result equality, request-bound source IDs, configured scope, page digest, authority/currentness/applicability/amendment proof and citation set. Any changed or unavailable proof suppresses the answer for a truthful clarification/regeneration path. Generic context never satisfies an official-policy citation. The actual send still uses the existing outbox authorization/idempotency/lease path.

Staff lookup follows the existing explicit HUMAN action: take the actual USER question plus fresh actor/grant/department/sensitivity/ticket snapshot, commit, run search/generation outside SQL, then refresh/check the snapshot and web proof before returning an editable draft. Keep citations as server-built URLs and labels; label unverified results as leads. The only send path remains the existing manual reply flow with current HUMAN state, permissions and revision CAS. No web result changes ticket state, creates an outbox message, or becomes a Student auto-reply through Staff assistance.

## Acceptance boundary

Before component acceptance, deterministic tests must prove: (a) complete Structured miss and complete RAG miss advance; a new match, `NOT_APPLICABLE` not validated by backend rules, ambiguous scope, incomplete context, error or stale proof makes zero web calls; (b) the external request contains only fixed public tokens and configured server domains; no raw case/history/identity/provider-controlled URL is transmitted; (c) absent/unknown config and consumed/exhausted reservation make zero search HTTP; committed unknown attempts are not refunded or retried; no generator `FREE_ONLY` fact substitutes for this gate; (d) only exact official scope and complete current/authority/applicability/amendment proof can satisfy YRU policy, while missing proof yields a useful lead; (e) generic/foreign citations never establish YRU policy; (f) student job/outbox changes and staff actor/ticket/message changes suppress stale output; web HTTP always runs outside SQL; Staff never auto-sends; and (g) no secret, raw query, case text, result body or private page proof enters logs/public metadata.

A passing fake-provider or PG test is component evidence only. Live provider account mode/no-PAYG controls, actual remaining free credits, approved official scope coverage, page-quality/currentness evidence, production worker/OA behavior and combined Flow A–F stay deferred until observed. If the provider account cannot be positively controlled as no-PAYG, mark the live connector unavailable; do not silently replace it with an unverified free service or a local-only “success.”

## Open risks for root

- **Vendor billing state is external mutable state.** `/usage` is not a reservation and cannot prevent another key or an account owner from changing settings; only an account owner-controlled free-only account plus app reservations makes the proposed route defensible.
- **Policy currentness is not inferable from web search.** Official pages often omit explicit effectivity, audience or amendment closure. The safe result may be a lead, and a missing authoritative current-consolidated page leaves policy answering impossible for that topic until evidence is published.
- **Existing worker retries can repeat work.** Search reservation identity must be durable and persisted before HTTP so lease takeover cannot turn an unknown attempt into a second charge.
- **Encrypted worker results currently persist.** Define cleanup after delivery/projection without breaking duplicate outbox verification; otherwise the claimed ephemeral source proof has an unbounded retention gap.
- **Search and generation are different disclosures and cost paths.** Query minimization limits the Tavily disclosure, but the existing generation path has its own FREE_ONLY/privacy contract and should not be described as anonymous or private by this proposal.
