## Contract

`prepareStructuredPublication(source:ImportSource, extraction:LocatedExtraction, binding:StructuredMappingBinding, mapping:unknown, request:unknown, key:string)` synchronously rebuilds the existing Mapping1 plan from source bytes and the saved located extraction. It accepts no caller-supplied rows, plan, digests, SQL identifiers, row IDs or lifecycle flags. The backend passes the retained source/extraction and saved review binding, not HTTP source objects. The existing mapper verifies bytes/checksum, extraction/report, exact mapping source identity and complete table/row disposition.

The strict descriptor-safe request is `{documentId, documentRevision, acknowledgment:{contentDigest, mapperVersion:'structured-mapper-v1'}}`; lowercase UUID, document revision 0..999999999 and lowercase SHA256. Preparation additionally requires canonical lowercase job UUID, job revision >=1 and extractionRevision<=jobRevision to match the fixed storage constraints. Review/extraction counters remain bounded by Mapping1. Unknown fields, getters, proxies, hidden/symbol properties and non-JSON input fail before request parsing. The key comes from the backend only.

Recompute the stable `structured-ack-v1` content acknowledgment using the same logic as review3. An absent, malformed or different acknowledgment fails. It intentionally excludes only reviewRevision and full plan digest: changing the saved review counter changes the full plan digest and row AAD, while content acknowledgment stays stable. Source, extraction, mapping, selected/excluded rows, constants, notes, transforms and quality observations remain covered. A matching digest demonstrates consistency with the supplied acknowledgment, not that a human actually approved publication.

Generate every row ID inside the backend using `randomUUID()`. Assemble each envelope's entire context from the recomputed plan plus the checked document tuple. Derive tableFirstRow from the checked row's sourceRow-rowIndex; never re-read mutable caller extraction after validation. Encrypt payload, fields, location and private source URL through STR-01C-0. No plaintext cell lexemes, constants' notes, raw mapping or source URL appear outside encrypted evidence in the returned artifact. Typed payload is private until later authorized persistence/projection.

Return a detached deeply frozen object with `schemaVersion:1`, `kind:'PREPARED_STRUCTURED_ROWS'`, dataset/registry/mapper, document tuple, checked binding, sourceChecksum/sourceFormat/extractionDigest/mappingDigest/planDigest, acknowledgment, rowCount, rows and `requiresFinalFence:true`. Rows contain `{id,payload,payloadDigest,context,evidenceEncrypted}` in mapper order. Source coordinates are the mapper's declared physical or logical kind; they are not a new assertion about PDF geometry. IDs/nonces change on a new preparation; plan and acknowledgment are content-derived. Detect duplicate generated IDs and fail rather than return ambiguous provenance.

The complete serialized artifact is <=16MiB, with the existing Mapping1 <=2000 rows and envelope limits. Incrementally account rows and envelope bytes before returning any artifact. Any source/request/mapping/key/envelope/size failure becomes fixed `STRUCTURED_PUBLICATION_PREPARATION_INVALID` with no source values, tokens, key or nested crypto/Zod details. No partial artifact escapes on failure; callers retain input bytes and drafts unchanged.

Extract the existing acknowledgment implementation into `lib/imports/structured-acknowledgment.ts` and re-export it from `structured-preparation.ts`. This preserves existing review/preview callers and avoids importing DB/staging services into the private pure assembly module. No acknowledgment algorithm change.

## Final persistence boundary

This function has no DB/filesystem/network/environment/log calls and no runtime approval caller. It cannot certify parser execution, active staff, saved-review receipt existence, document authority/currentness/applicability, installed schema or a committed effect proof. The future publisher must load actual source/review/extraction itself, prepare outside SQL, then re-check active actor/job/extraction/review/target/family revisions under existing locks and atomically insert provenance + matching typed rows + mode-specific receipt. A prepared artifact cannot bypass that fence. Registry remains installed:false; STRUCTURED/BOTH approval remains explicitly unavailable. No new human setting is required now.

## Acceptance

Tests first: 35 synthetic mapper dataset/format combinations with real envelope decrypt and payload/source/context parity; multiple rows/tables and explicit exclusions; stale/missing/changed acknowledgment; actual source/extraction/mapping edits; full digest vs stable review acknowledgment; backend-owned UUID/nonce and no plaintext private fields; strict request attacks and storage counter consistency; immutability/input preservation; invalid key/size fail without partial output. These are synthetic located fixtures, not actual all-format parser/corpus/live acceptance. Focused and full unit/type/lint gates, independent source review when available, owned-file credential/whitespace checks and dated report. SQL/HTTP/build/browser gates are not attributed to this unused Node component.
