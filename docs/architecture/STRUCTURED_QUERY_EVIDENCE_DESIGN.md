## Query1 and exact matching

Input is strict `{version:1,dataset,filters,limit}` with one of seven registered dataset literals and integer limit1–20. Every key is required at root; filter keys are optional, unknown/undefined/getter/proxy/inherited/hidden/symbol/non-JSON input fails. Snapshot32KiB/256nodes prevents side effects; snapshots/results are detached and frozen. No defaults, implicit era/year/context, coercion, text-to-SQL, dynamic column/operator identifiers or fuzzy labels. Text preserves exact well-formed lexemes, bounded like its payload field, rejects Unicode Cc. Optional nullable `major_name:null` means exact null; other null filters fail. Date/timestamp/decimal validators reuse current source contracts.

| academic_calendar_events | academic_year,semester,student_type,event_type,title,occurs_on,start_date_from,start_date_to | academic_year,semester,student_type |

`assessStructuredQuery` returns READY or CLARIFICATION_REQUIRED with fixed missing field/group names only; alternatives use `service_code|name`, `code|name`, `name|form_url` and `title|effective_at`. `matchesStructuredPayload` validates both query and payload, rejects incomplete queries with a fixed code, and evaluates literal equality/inclusive bounds without SQL. It is a predicate on a supplied validated row, not retrieval, authorization, ranking, contradiction resolution or a source of current data. Backend may fill selectors only from explicitly known user context; program_name is not inferred from programCode.

Money/credit ranges use BigInt-scaled exact decimal strings, never floating point, preserve source decimals and include boundaries. Reversed ranges fail. Without an explicit currency filter, fee bounds compare nominal source amounts only; they do not convert currencies or establish comparable currencies for an answer. Future retrieval/answer validation must resolve that context. Calendar occurs_on treats null end_date as a single-day event at start_date; fee null effective_to and announcement null effective_to are open-ended. Calendar start_date_from/to restrict the start date, not interval overlap. No clock is consulted: effective selectors are explicit; future retrieval always separately applies document effective/current/history gates. Priority ranges are integers0–100.

## Internal row reference1

Strict serialized reference includes schemaVersion1,dataset,registryVersion structured-v1,mapperVersion structured-mapper-v1,rowId,documentId,documentRevision; jobId/jobRevision/extractionRevision/reviewRevision; sourceChecksum/extractionDigest/mappingDigest/payloadDigest/planDigest; tableIndex,rowIndex,tableFirstRow,sourceRow,coordinateKind,sourceLocation; existing complete ruleProof. UUIDs must be lowercase canonical; revision counters use existing mapper bounds (job0+, extraction/review1+, document0+). Row/table indices use extracted bounds; sourceRow/tableFirstRow are one-based.

`validateStructuredRowReference(reference,payload)` snapshots/safely parses both, validates the dataset payload, and recomputes the existing domain-separated structured-payload-v1 hash. Source locations are strict existing location schemas and must identify a table. XLSX→WORKSHEET_CELL/CSV→CSV_RECORD and PDF/DOCX/HTML→EXTRACTED_LOGICAL only. Reference tableIndex is the zero-based extracted-table array index; existing validateLocatedExtraction enforces location.tableIndex=reference.tableIndex+1. sourceRow equals tableFirstRow+rowIndex for every format; XLSX/CSV tableFirstRow equals location.rowStart and row bounds contain sourceRow. Logical formats retain their actual table.firstRow, not an assumed1, including noncontiguous PDF fragments. It does not claim original DOM/XML geometry. Fixed schemas preserve extracted bounds and no location fetch occurs.

Equality checks compare all serialized reference fields, including complete ruleProof and exact location, after strict detached parsing. It does not prove either reference matches live database state. These unkeyed hashes are consistency checks, not authorization/signatures. Payloads/locations can be fabricated consistently; the future backend must bind references to immutable persisted provenance under authorized document/rule selection, re-read during finalization/dispatch, and reject all drift including uncited context. There are no dedicated raw-cell, mapping-note, private-original-path or token fields. This is not sanitization of arbitrary field contents: the existing HTML location schema permits general HTTPS sourceUrl values, so a fabricated reference can contain credential-like URL contents. Mapper-produced locations have upstream verified import-source validation; an arbitrary parsed reference is not safe for public disclosure. Public citation projection must separately enforce persisted-source binding and URL disclosure policy. This parser remains internal and unused by endpoints/tools until that contract is implemented.
