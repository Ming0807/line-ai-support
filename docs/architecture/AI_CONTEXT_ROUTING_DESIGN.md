# RAG-01A — semantic context routing

Root,8October2026; CH023/028/031, original overview §§17–19/21 and master §§23/28/31/66/69 Flow E. The current router always has confidence0 for unselected messages, so every subsequent message asks for context even when it is clearly a new library question during a Registration HUMAN case. Existing opaque choices/state guards are preserved. This slice adds a production free-gateway semantic proposal; troubleshooting/outcome/escalation recommendations remain RAG-01B.

Production inbox worker may request a bounded8-second classification only for an eligible Student TEXT event with existing contexts, when AI is enabled. Before HTTP, an owned lease snapshot checks channel/hash/typed event, active existing session, prior-arrival spam threshold and existing LINE-message deduplication. It reads at most12 active contexts (overflow disables automatic selection), minimized current topic/ticket summary and bounded previous actual USER text. No technical LINE identity, anonymous code, internal IDs or staff text enters the model prompt. Contexts have ephemeral C1…C12 labels. Raw text is untrusted data; minimization cannot guarantee that user-authored text contains no personal details.

Read transactions use statement/lock bounds and processing-lane→sorted conversation locks. Snapshot commits before FREE_ONLY gateway/network/usage I/O. A strict proposal has NEW/CONTINUE/ASK, nullable candidate code and confidence. Backend requires confidence>=.8, exact known candidate mapping and consistent decision fields; an unavailable/invalid/tool-bearing/low-confidence result uses the existing context prompt. No keyword router or latest-ticket fallback is introduced. The existing30-second inbox lease is not extended or refreshed; near-expiry snapshots skip classification, and the ordinary final lease check still suppresses obsolete workers.

Classification advice is ephemeral internal data bound to the exact inbox event, session, question digest and complete minimized context digest. Before applying it inside the normal business transaction, reload current session/candidates/topics/actual USER history and compare digest. HUMAN takeover, closure, new messages or other source changes discard the hint and ask when current candidates exist. Model labels map to server-loaded conversation IDs only. Explicit owned postback choices bypass semantic classification. NEW starts a separate AI conversation; CONTINUE routes exactly to the still-current AI/HUMAN context. HUMAN never gets an automatic AI response. This stage cannot create/change/resolve a ticket, send a model answer or infer a university rule.

Library `runInboxCycle` accepts an explicitly injected classifier; the production `scripts/worker.ts` binds the existing configured free gateway. Existing test callers without the classifier preserve their controlled behavior. Actual PG tests inject classification only and prove outsideSQL/canonical ownership/fresh-source/lease/spam/duplicate checks and unchanged HUMAN behavior. The production adapter's prompt/output/cost/deadline contract is tested separately. No schema or human configuration change is required.

Acceptance: high-confidence new Library question with live Registration HUMAN context creates a new AI job and retains the old ticket; same-problem context reaches the exact HUMAN ticket without AI job/outbox; multiple contexts map to the selected current candidate; malformed/unknown/low-confidence/stale/expired hints ask or fail safely; spam/duplicates/postbacks make0 classifier calls; model prompts exclude explicit private identities/IDs/staff text; provider HTTP never runs inside SQL. Final live free classification/Thai quality/OA remains deferred.
