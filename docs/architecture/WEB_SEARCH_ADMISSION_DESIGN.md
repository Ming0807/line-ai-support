# ADV-05C-2-R — private durable search admission

9 October 2026 root, CH032/052/USR-WEB, master§32/original§27. Depends on [C2-Q](SOURCE_CASCADE_DESIGN.md) and the [fixed adapter contract](../superpowers/plans/2026-10-09-yru-free-web-connector.md). This is a frozen root implementation contract under continuing V1 authorization, not a live search/provider/source-authority acceptance.

## Alternatives and selected boundary

An in-memory counter loses crash/deduplication guarantees. Separate mutable quota counters introduce reset/drift/privilege concerns. Select a retained private attempt ledger: an indexed count under one short transaction advisory lock bounds all keys/consumers, with a DB trigger protecting direct service inserts as well as the application helper. No HTTP occurs until the reservation transaction commits. Provider account billing is external and still requires owner-controlled free/no-PAYG settings.

Root owns one CLI-generated additive migration, `lib/knowledge/web-search-admission.ts`, `web-search-runtime.ts`, unit tests, actual owned `tests/database/web-search-admission.integration.ts` and runner registration. No existing public DTO, browser route, provider inference setting or university source approval changes. Normal/local+DEVELOPMENT remains36 until future guarded activation.

## Fixed ledger and database enforcement

Private RLS `web_search_attempts` has request_key text primary key and attempt_id UUID unique/default; owner_digest text, consumer STUDENT|STAFF, purpose YRU_INFORMATION|GENERAL_PUBLIC, closed C2-Q topic, nullable academic_year2400..3000, reserved_at timestamptz, quota_day date, quota_month date, observation UNKNOWN|SUCCESS|ERROR, nullable http_status100..599, nullable provider_request_id UUID and credits null|1. Both digests are exactly64 lowercase hex. Purpose/topic/year combinations equal the frozen C2-Q registry. No raw question/query/key/LINE identity/URL/result body or plaintext technical owner IDs. Base identity/period/purpose fields are immutable; retain attempts without DELETE/TRUNCATE. Initial observations must be UNKNOWN/null; only one UNKNOWN→SUCCESS|ERROR observation write is allowed. SUCCESS requires HTTP200/UUID/credits1; ERROR cannot claim credits/request ID, HTTP may be null. Observation is diagnostic and never refunds a reservation.

INSERT acquires `web-search-quota:v1` xact advisory lock, derives DB-clock UTC day/month and overwrites supplied timestamps/periods. At most50 reservations per UTC day and500 per UTC calendar month across all keys and both consumers, counted from retained rows. These are explicit engineering ceilings below the currently advertised free monthly credits, not university requirements or a vendor billing guarantee. A duplicate request key must not increment counts. Index `(quota_day)` and `(quota_month)` supports exact counts. Service_role gets SELECT/INSERT and UPDATE(observation,http_status,provider_request_id,credits) only; no table-level UPDATE/base-column UPDATE/DELETE/TRUNCATE. Browser/public roles get no table/function access. Trigger functions are private SECURITY INVOKER with empty search path and exact service execution. No SECURITY DEFINER or broadly writable counter table.

Root concurrency refinement before acceptance: INSERT requires READ COMMITTED. A retained REPEATABLE READ/SERIALIZABLE snapshot could predate a competing reservation despite acquiring the advisory lock. The guard therefore rejects those insertion transactions with fixed UNAVAILABLE instead of counting an old snapshot; actual owned PG covers this denial. The application helper uses the existing fresh-transaction default. Multirow statements must also fail atomically at the ceiling.

`reserveWebSearch(pool,input,key)` accepts strict own JSON `{consumer,operationId,ownerId,purpose,topic,academicYear}`, UUID operation/owner identities and the C2-Q pair/year validator. It domain-separates HMAC-SHA256 request key from consumer/operation/purpose (topic/year/owner changes cannot reopen the same operation/purpose); separately hashes consumer/owner as owner_digest. The existing server encryption key supplies the secret without new key configuration. In a fresh transaction with2-second statement/lock bounds, acquire the global advisory lock, check duplicate then complete day/month counts, insert and commit. Return RESERVED with opaque attemptId, DUPLICATE or EXHAUSTED. Missing table/permission/timeout/transaction errors return UNAVAILABLE and grant no HTTP. Use the existing transaction helper. SQL guards independently enforce the same ceilings and stamp/retention invariants for direct inserts.

`observeWebSearch(pool,attemptId,outcome)` validates only the fixed observation shape and conditionally updates UNKNOWN; repeated/replayed observations leave the first value. An observation failure must neither refund/retry nor discard a successful in-memory result; return false/fixed safe diagnostic only. Do not retain provider error strings.

## Root runtime gate

`createWebSearchRuntime` composes explicit server configuration, the adapter and committed admission. Its request uses the same private owner/operation and closed query fields; it returns fixed NOT_CONFIGURED, FREE_ONLY_UNVERIFIABLE, QUOTA_EXHAUSTED, ALREADY_ATTEMPTED, UNAVAILABLE or READY. No public route/caller is added here. The future production caller must establish complete internal misses and fresh source/lease/actor scope before invoking it; this helper cannot infer that authority.

Default disabled. Before even GET usage, require a key and server owner attestation `RESEARCHER_NO_PAYG`, attested key SHA256 matching the actual configured key, and an ISO UTC timestamp not future and at most24hours old. This is an engineering attestation lifetime, not a vendor promise. A fresh bounded usage observation must name exactly Researcher, zero paygo usage/limit, positive key/account limits no greater than1000, and remaining key/account credits. Unknown/paid/changed plan/shape stops. Missing/cancelled/invalid requests perform no search POST or reservation. Usage errors stop; no fallback/retry. The selected owner must not enable automatic upgrades or paid services; the app cannot prevent external mutation after observation.

Reserve and commit exactly1 attempt before POST. If cancelled or configuration expires afterward, leave it consumed and send nothing. Failed/timeout/unknown calls remain consumed; takeover receives ALREADY_ATTEMPTED. A valid success/empty response receives a single safe observation. No runtime retry, paid fallback or secret/raw-query logging. Search and generation billing policies remain separate. Actual Student job/Staff operation identity, web proof/result persistence/retention and complete internal-miss delivery integration still require the subsequent root contract.
