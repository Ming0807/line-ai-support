# ADV-01 — authenticated self-service Staff OA binding

Root,8October2026. CH054, original overview§46–48 and master§54. Dependencies: active Supabase staff login, existing encrypted Staff ingress, private staff identities, scoped alerts/commands and delivery locks. No Student identities are created.

An authenticated active staff member creates a10-minute one-use binding command in Settings and sends it to Staff OA from their own LINE account. A256-bit random token is purpose-hashed for lookup and encrypted for issuer-only idempotent request recovery; raw LINE identities remain encrypted/hash-indexed. The public status DTO exposes only bound/pending/expiry observations, never technical IDs or hashes. Creation/replay is bound to actor/request UUID; creating a different challenge invalidates older ones. Already-bound accounts must explicitly unlink before replacement. A LINE identity already attached to another staff account is rejected; neither token possession nor LINE text creates staff roles/accounts/grants.

Staff signed durable processing validates the exact command, token expiry/consumption, current active account and both identity uniqueness constraints. Bind/unbind/challenge mutations serialize under a private binding catalog lock and acquire the existing `delivery:STAFF:<staff>` lock before changing identity; started delivery completes first, later delivery observes inactive/new binding. Explicit unlink invalidates all challenges and staff action tokens. Same-user consumed retries are idempotent; another user cannot replay them. All SQL is local to the existing lease transaction; no LINE HTTP in SQL. The setup command needs no Student/ticket routing and is not an AI keyword router.

Settings shows the current binding, temporary copyable command, expiry, refresh and explicit unlink confirmation. Dashboard polling observes completed binding; there is no invented LINE success reply or unconditional notification. UI never displays raw LINE IDs. POST `/api/staff/line-binding/challenge`, GET/DELETE `/api/staff/line-binding` use active self identity, private headers, same-origin/strict bounded JSON and fixed errors. Backend may audit fixed binding event names with no command/identity payload.

Root owns auth/privacy/schema/contracts/process integration. Human sends the command into the actual Staff OA only during deferred live setup. Owned fixtures test real PostgreSQL transactions without live messages. Source does not prescribe token lifetime or command syntax; these are recorded engineering choices.
