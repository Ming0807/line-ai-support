## Confirmed source observations

- `lib/ai/assistant-orchestrator.ts` passes the original snapshot to lookup for LOOKUP/MIXED_REPLY and deliberately ignores the model's `query`. This protects against invented scope; it also means the complete contextual query requested by the decision prompt never reaches embeddings.
- `lib/knowledge/configured.ts` binds natural lookup with `createKnowledgeProducer(bound)` without a retrievalQuery. `answer-producer.ts` uses `options.retrievalQuery ?? snapshot.question`, then embeds that value. Scope/planning and answer prompts receive the last four owned history turns. Supplying history to those prompts does not make the vector query contextual.
- This is a confirmed integration gap for short reference-dependent RAG questions, not yet proof that every observed wrong answer is caused by retrieval. Original scope/year/applicability is validated from original USER text/history; the model's rewrite must never replace that authority.
- The legacy support producer already uses source-validated advice/searchText for TROUBLESHOOT and can retain the actual prior USER problem with the current question. It is inaccurate to say every running YRU path has no contextual query support.
- The RAG answer prompt already requires eligible evidence only, all relevant chunks, source order, prerequisites/warnings, honest limitations and returned citation IDs. Backend publication/visibility/current/effective/applicability/fingerprint/rule-proof and delivery checks remain separate. A strict prompt alone is not a semantic correctness guarantee.
- Retrieval uses exact filtered cosine similarity, default threshold0.65, bounded complete rule groups and at most12 returned chunks. Hybrid/BM25 is not present. Its absence alone does not establish the cause of a particular failure or justify changing ranking thresholds.
- The configured embedding infrastructure is offline CPU multilingual-e5-small/384, infrastructure query/passage prefixes and normalized vectors. Inputs beyond the tokenizer budget are rejected, not silently truncated. No evidence yet justifies replacing the model, downloading another cache or re-embedding the corpus.
- Chunking preserves heading/paragraph/table blocks, grapheme boundaries and source locations, followed by reviewed token-bounded preparation. Current A14 and A15 owned reports each retrieve the exact eligible reviewed synthetic document; A15 supplies all six chunks. Their current source-based answers therefore cannot be explained by a wrong-document retrieval in those two runs. This is not a whole-corpus chunking-quality pass.
